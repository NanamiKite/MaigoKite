# MCP 集成

> 权威范围：当前传输方式、客户端/进程所有权、工具发现和调用边界。
> 本地技能格式见 [技能](../skills/skill-lifecycle.md)，策略见 [工具权限](../security/tool-permission.md)。

## 1. 当前生命周期

Python 核心服务是唯一 MCP Client 所有者，API 层和 Electron 不直接调用 MCP 工具。2026-10-10 已用官方 Python SDK 替换自研 stdio 协议实现；`agent.mcp.MCPClient` 保留配置校验、SDK 生命周期桥接、结果转换与有界资源读取，协议仍由 SDK 负责。

Linux 本地定向验收覆盖真实 SDK stdio 子进程、发现/调用/审批、取消后连接复用、超时、关闭和启动失败清理。2026-10-15 又通过真实 Core 的扩展配置保存/应用、失败保留健康配置及重启加载生效配置；凭证与故障分支的准确范围见 [当前验收状态](../../project/Roadmap.md#当前验收状态)。

```text
用户保存扩展配置（首次可由 YAML 提供）
→ 空闲时显式应用；Core 重启加载上次生效配置
→ 校验 command/args/cwd/env allowlist
→ SDK stdio_client 启动进程
→ SDK ClientSession 协商 / initialize
→ 分页 tools/list 与工具注册
→ 受控调用
→ Core shutdown 等待 SDK 上下文退出 / 子进程回收
```

当前 command 为 argv，不经过 shell；cwd 由 Core 限制在工作区。SDK 合并其平台基础环境白名单与 MaigoKite 允许的环境项/显式配置凭证，不继承完整环境。清单只展示命名空间/传输方式/运行状态/工具名。stderr 当前被丢弃，不能假设已能在诊断页读取。

SDK 的 AnyIO 上下文由单个连接所有者 `asyncio.Task` 进入和退出，以适配 Core 初始化/关闭可能位于不同任务的情况；它不调度工具，也不实现请求队列或取消树。单次工具调用取消不关闭共享连接；关闭等待所有者退出。协议解析、请求 ID、响应关联、初始化消息和进程终止由 SDK 承担，不读取 SDK 私有字段。

连接可用性还检查 stdio 返回的 AnyIO 接收流的公开 `statistics()`：读端关闭或写端 EOF 后，即使所有者仍在等待关闭，也不再显示为已连接或接纳新调用。设置查询、工具筛选与已有恢复入口共用该判断；不添加后台探活，不抢读 SDK 消息，不自动重发原工具操作。旧连接资源仍在应用替换或 Core shutdown 时经 SDK 回收。此 EOF 补漏仅完成源码核对，未运行新增验收。

启动/发现限时 30 秒（SDK 退出清理另计），失败不注册部分工具，不阻止其他服务和 Core 启动。页面区分停用、连接中、已连接、缺凭证、目录失效、超时和连接错误；“已连接”仅表示本地 SDK 会话已建立，不是持续远端健康检查。目录扫描在显式应用或启动时进行；恢复原连接不重扫 Skill。健康自动重启、独立沙箱、资源配额、运行中热替换、SkillVersion/Grant 和远程传输方式都未交付。

### 配置与凭证管理

侧栏“扩展 → MCP”可添加或编辑 command、args、cwd、环境变量名、结果适配和工具请求时限，启停或移除服务器。工具请求默认 30 秒，可设置为 1～660 秒；发现和资源读取的限制不因此扩大。两份配置职责不同，均不含凭证值，也不是执行状态：

- `workspace_settings.extensions.config` 保存期望配置。保存不改 YAML、不启动进程，revision 防止旧页面覆盖新配置。
- `extensions.applied_config` 保存上次生效配置。Core 重启优先加载它，不用未应用的编辑替换待审批任务的服务。

没有数据库快照时才读取 YAML。升级前缺少生效快照时，沿用当时的保存配置/YAML 建立初始记录，不能重建未知的历史配置。

应用由个人工作区 owner 发起。Python API 读取密钥链；Core 暂停新运行准入，确认没有运行或等待中的任务、审批和提问后，准备候选目录、重连 MCP 并打开候选执行入口。Skill 扫描出错或任一启用 MCP 未连接时，不提交候选版本。

准备成功后才替换原 LangGraph 实例。配置和凭证未改变的健康连接直接复用，显式应用通过其 SDK 会话刷新工具发现；需要替换的连接先准备成功，再关闭旧连接。准备失败只清理本次新建资源，保留原配置、目录与健康连接，不先停掉全部 MCP。若服务不允许新旧进程同时存在，应用会明确失败并保留旧服务，不暗中强停。旧资源关闭失败时保留其所有权，下次应用或关闭再清理，并在快照的 `extension_error` 中提示。模型客户端、Browser、Repository 和 UI 订阅不更换。

“恢复已有连接”使用上次生效版本，允许存在待审批/待回答任务，但仍拒绝有活动运行时执行；它不应用已保存的新配置，也不重扫当前 Skill 目录。健康 MCP 的连接及已应用工具目录保持不变，只恢复缺失连接。部分服务器缺凭证或启动失败不丢弃其他服务器的恢复结果，快照逐项报告失败，并记录 `extensions.restored` 的 `partial` 审计。批准 MCP 工具前先确认对应服务与确切工具可用；其他服务失败不阻断该项批准，目标服务失败则不消费审批。Core 仍校验原工具名称、参数 hash、策略和版本，恢复连接不是重新授权，也不是 MCP 副作用重放。拒绝审批不要求恢复凭证。

`secret_env` 只保存环境变量名，值通过既有凭证 API 存入系统密钥链，引用为 `mcp.<namespace>.<ENV_NAME>`。Python API 在同进程内注入所需值，不写普通配置、checkpoint、审计或 GET 响应。没有密钥链时不退回明文文件。`env_allowlist` 允许继承 Core 启动环境中的指定变量，两类变量不得重名。

Core 重启不保留内存凭证。显式应用、恢复连接、新聊天和 MCP 批准按所需范围准备 MCP 凭证；普通执行入口只恢复上次生效配置，不应用待生效编辑。恢复只读取缺失连接的凭证，新聊天允许可选 MCP 部分恢复；文件任务恢复、回答提问及原生工具批准只准备模型/搜索凭证，不启动或等待无关 MCP。Runtime 仍核对 checkpoint 和每次工具调用权限，跳过无关准备不等于允许不可用工具。MCP 批准要求目标连接和确切工具可用，失败不消费决定。也可手动点击“恢复已有连接”，通常无需重新填写。拒绝不依赖 MCP 连接或凭证，不为被拒绝的操作启动服务。

凭证更新/清除与配置保存均不会热改活动进程环境，凭证值在下次显式应用或重建缺失连接时注入；恢复其他服务器不会替换健康连接的凭证。复用时保留该 client 实际启动环境对应的内存凭证快照，不采纳并发恢复请求中新读到、但未安装到进程的密钥；显式应用也按实际环境比较，因此仍能识别凭证轮换。移除 MCP 配置不会删除可执行程序、源目录或密钥链内容；清除凭证是单独的显式操作。应用任务由 Core 持有，调用方断线不提前释放准入锁，Core 关闭会等它完成清理；这只是资源生命周期接线，不是插件框架或任务状态机。只提供本地 stdio 接入，不声称已有包市场、远程安装或 HTTP 传输。管理主路径已有上述真实 Core 回执；密钥链凭证重启/轮换、并发恢复/应用中断和扩展设置 GUI 全流程不在其通过范围内。

## 2. 发现与参数

结构定义/JSON-RPC 字段以 MCP 标准和锁定 SDK 为准，不维护协议字段副本。SDK 模型通过公开 `model_dump(by_alias=True)` 传给既有产品包装，保留 `inputSchema`、`isError` 等字段名；发现遍历分页并限制总时间、重复游标和最大页数，失败不返回不完整目录。

- 工具发现与审批恢复共用规范化命名空间前缀，保留已有工具名；配置拒绝 `server` 与 `server_` 这类规范化后冲突的组合，单独使用 `server_` 不影响审批恢复。名称、描述和结构定义大小受限。
- Server 自报权限不构成授权；默认风险和 destructiveHint 只能收紧，由 ToolPolicy 最终判断。
- 参数复用 JSON Schema 校验与现有错误 DTO；引用不能在校验时联网或读取外部文件。
- 模型可见工具范围与执行授权要一致；全面按主体能力过滤仍须验收，不用“发现成功”宣称授权完成。

## 3. 调用与错误

已连接 MCP 工具通过公开转换接入唯一 LangGraph Runtime，协议由官方 SDK 桥接，不保留第二套 MCP 协议客户端。代码替换不等于远端取消或恢复已经验收：

```text
ToolRegistry resolve / 参数规范化
→ PermissionPolicy / 现有 Approval
→ MCP tools/call（请求超时）
→ ToolResult / audit / 活动投影
```

返回内容是不可信数据，不授予权限。SDK 负责协议结果模型校验；产品包装仍保留非对象结果的 MCP_INVALID_RESULT 防御分支。`isError: true` 映射为 MCP_TOOL_ERROR/ToolResult.failure，保留原始结果和检查连接、凭证、参数的简短提示，不记成工具成功，也不伪造不存在的设置链接。

连接错误不盲目重试副作用。请求/工具调用 ID 用于关联；完整追踪上下文传播和 stderr 脱敏采集尚未接线。配置示例只在 [配置指南](../../user-guide/Configuration.md) 维护。

SDK 的公开进度回调映射到同一工具调用的 `tool.started`，携带 `progress / total / title`。包装层最多每秒更新一次，回调有时限；完成或取消后不再接受该调用的进度。界面更新已有活动，不重置开始时间，也不把进度写进助手回复。该通知不是新的任务状态或后台任务协议。

### 3.1 天线结果资源适配

`result_adapter=antenna_design` 是显式启用的宿主结果投影，缺省 `none`；不根据工具描述、服务名或端口猜测。切换时通过既有 apply 刷新工具包装，可复用配置和凭证未改变的健康连接，不另起服务。

所选服务的 `antenna.solve / get_result / render` 返回计算结果，`antenna.design / export / get_delivery` 返回候选包；这些成功回执进入 `agent.integrations.antenna.AntennaResults`。调用仍走 ToolPolicy、审批和审计，不因服务自报只读而降权。适配器校验 `schema_version=1`、对应 run ID 或 delivery ID、有界摘要和固定资源清单，再通过相同 SDK 会话 `resources/read` 核对 URI、MIME、字节长度、SHA256 和 PNG 文件头，写入当前对话目录。

资源读取不开放为任意 URL 下载或模型工具；单文件最多 16 MiB，整个导入最多 48 MiB、30 秒（文件写入清理另计）。限制约束接受的资源内容，不等于 SDK JSON-RPC 分配上限或系统磁盘配额。每次读资源和落盘前查询当前目录/权限；只读时不继续写，写入不覆盖不同内容的已存在文件。

计算副本保留 PNG、SVG、JSON 和可用 MAA；候选包固定包含报告、几何、尺寸、模型、材料、评价、验证、施工调试、复算和 ZIP 十项资源。PNG 复用聊天图片，其他文件使用工作区预览或鉴权下载；宿主不解压 ZIP。目录标识由命名空间、结果编号和资源内容 hash 决定，重复取回补齐同一副本，不覆盖用户修改。

最后写 `import-receipt.json`；部分导入失败保留已校验文件，以 `import_complete=false / import_warning` 和稳定警告码提示，不重跑求解或重新导出。取消等待当前本地写入线程结束，但线程结束不等于远端 worker 停止。数值完整、图不完整时可导入数值，随后通过 `render` 补画；丢失交付回执用 `get_delivery`，不是 `get_result`。

模型只得到紧凑回执与引用，不接收原始数值数组或图片字节。`antenna_receipts.py` 另对 `optimize / get_optimization / evaluate / plan_design` 提取指标、停止原因和预算，去掉重复 MCP 文本与逐点证据 hash；完整原始回执保留供检查。求解与评价仍属于独立包，宿主不实现工程算法。

领域包独立安装，不导入主应用或 LangGraph；项目求解准入保存在服务自己的 SQLite 中，不进入主应用 Repository。Linux 已有真实 MCP、生产 Core 审批/取消、重启取回、冲突保护和导入的定向记录，具体范围见 [路线图](../../project/Roadmap.md#2026-10-23-天线恢复与生产调用验收)。这些结果不证明任意第三方 MCP 可恢复，也不覆盖完整 GUI、自然语言编排或 Windows。

## 4. 取消、关闭和隔离限制

`asyncio.CancelledError` 向调用方传播，不被转换成成功结果或重试。原生 `asyncio.timeout` 覆盖整个 SDK `call_tool` 的发送与等待；通用 MCP 超时仍提示远端执行结果可能未知。当前锁定 SDK 的本地等待取消不能证明已发送协议取消，更不能证明远端副作用停止，不为此重写协议。

天线适配单独处理自己发起的 `solve / render / optimize / design`：通过公开 `_meta` 传随机 `operation_id`，取消或请求超时后调用 `antenna.cancel`，最多额外等待 10 秒。服务只有在对应 worker 退出、清理和证据保存后才确认，身份不符不能停止其他调用，共享 MCP 连接不关闭。缺少回执、旧服务或断线时仍提示“远端停止未确认”，不得自动重算。这是该扩展的停止确认，不是通用 MCP 取消保证，也不是实验性 MCP Tasks 接入。

Core 关闭先停止并等待自己的调用，再退出 SDK 上下文，由 SDK 关闭 stdin、等待并按平台回收进程；不再自行轮询 returncode 或发送 killpg。单个连接关闭失败不跳过其余连接，错误汇总到 Core。上述本地验收不覆盖任意第三方服务器崩溃、Windows 子进程树或远端副作用停止。

核心服务当前最小环境/cwd 检查不等于完整 OS 沙箱。凭证来自显式环境 allowlist 或密钥链注入，文件/网络/进程资源隔离尚未完整实现；不得把假想 SkillGrant 写成实际授权器。添加 stdio 程序意味着授权以当前用户身份启动它，工具审批不能限制该程序在初始化时自行产生的副作用。

## 5. 后续准入

本批采用 `mcp>=1.28,<2`（锁文件为 1.30.0），不安装 CLI extra。已调查 [官方 v1 维护线](https://github.com/modelcontextprotocol/python-sdk/tree/v1.x) 和 [v2 迁移说明](https://py.sdk.modelcontextprotocol.io/migration/)：v1 仍接收关键修复，能满足现有 stdio/字段兼容；v2 涉及协议、类型和 HTTP 依赖栈变更，本批不顺带扩大迁移。后续升级需重新核对维护状态及取消需求，不能无限期冻结版本。

使用新代码前按 [开发指南](../../development/DevelopmentGuide.md) 同步根环境。后续收口使用已有锁定环境完成定向测试，未安装或升级依赖；本地 fixture 的通过不能标记为外部 MCP 服务 LIVE PASS 或任意工具恢复通过。

远程传输方式只有真实个人服务需求后才设计服务身份、连接会话与网络信任；不预建多租户/插件 Manager。新能力须通过发现、错误、超时、取消、异常退出、资源回收与凭证隔离测试，见 [测试与验收](../../testing/TestPlan.md)。
