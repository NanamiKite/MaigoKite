# 记忆与检索边界

> 权威范围：长期信息、原始材料与派生检索的职责和生命周期。
> 运行上下文预算/摘要见 [智能体运行时设计](../../design/AgentRuntime.md)，业务表见 [数据库设计](../../design/Database.md)。

## 1. 当前实现与未实现

| 能力 | 实际边界 |
| --- | --- |
| 会话消息 | SQLite 持久化，作为聊天历史来源 |
| 输入裁剪/任务内摘要 | 运行时能力；同对话成功回合可继承 checkpoint 摘要，不等于跨对话长期记忆 |
| 显式用户偏好 | 当前界面称呼等产品设置，独立于用户记忆 |
| 用户记忆 | 当前用户按工作区文件夹手工 CRUD、关键词查询、遗忘与审计；旧的未归属记录单独管理 |
| 手工记忆的请求投影 | 文件夹与对话同时开启时，每次主模型调用前读取，限预算附带；不写回历史/checkpoint |
| 自动记忆提取/确认、语义检索 | 未接入主循环 |
| 知识库、向量嵌入/FTS/vector | 未接线；状态页不代表索引可用 |
| 导出/批量清理/保留期设置 | 未完整交付，不承诺已有 API |

未接入的 Embedding、知识库、Storage、Timeline 基础设施继续保留，其源码状态和限制见 [后端设计：保留但未接入的基础设施](../../design/BackendDesign.md#6-保留但未接入的基础设施)。修复这些模块的导入或空实现，不表示已加入记忆请求投影、Core 或工具调用链。

保存记忆后，还需同时开启文件夹和对话开关、匹配条目归属，并有足够的请求预算，条目才会附带到模型请求。附带条目不保证模型会在回答中采纳它。当前只投影手工条目，不提供自动提取或语义检索。

本批已补文件夹归属、文件夹/对话默认关闭的开关、管理 API 与主模型请求投影。Runtime 就绪时 `scoped_memory=true`，表示后端可处理该功能，不会自动开启用户的开关。源码已接线，未运行本批测试、数据库迁移或模型调用。

## 2. 职责与事实来源

| 对象 | 事实 / 派生 | 规则 |
| --- | --- | --- |
| 消息 / 用户原始文档 | 权威材料 | 不被摘要覆盖成唯一副本 |
| 用户记忆 | 用户输入或可追溯的长期信息 | 可查看、修改、遗忘，记录来源 |
| 运行上下文 | 运行投影 | 生命周期归运行时，不另存重复消息库 |
| 摘要 | 有损派生 | 检查点内用途和跨任务限制见 AgentRuntime |
| 数据片段 / embedding / FTS/vector | 未来派生索引 | 必须带来源/版本，可删除重建 |

不创建另一套 append/snapshot/trim 等自研上下文协议；裁剪/压缩优先使用成熟运行时。产品偏好、长期记忆和外部资料检索不能合成一个无边界“记忆”模块。

## 3. 长期记忆安全约束

用户记忆字段由 [数据库设计](../../design/Database.md) 和 Repository 定义，接口由 [API 设计](../../design/API.md#34-用户记忆与数据摘要) 定义；本文不重复字段清单，也不增加未实现的接口。

- 查询和写入强制工作区 + 当前用户范围，再按文件夹隔离。`personal` 只是个人数据范围，不能据此把不同文件夹的记忆混入提示词。文件夹不是操作系统安全边界，也不会隔离宿主凭证。
- 记忆归属由文件夹 ID 与规范化根路径共同确定；默认目录配置改变不会继承另一目录的记忆。历史记录保留空归属，不猜测属于哪个项目；删除文件夹后相关记忆回到未归属，不能流入默认目录。
- 文件夹与对话两层使用开关均默认关闭，必须同时开启才允许使用该目录记忆。分岔新对话默认关闭；移动对话或删除其文件夹会关闭对话开关，不继承新目录授权。
- 关闭、修改、删除的目标是后续请求；已经发出的模型请求、历史回复、用户复制的内容不能被追溯撤回。同一目录内不同工作流需要干净上下文时，应新建关闭记忆的对话，而不是仅关闭既有长会话的开关。
- 来源是用户直接输入，或未来明确可追溯的源记录；自动提取若实现，需区分 proposed/confirmed，敏感或高影响信息先确认。
- API 密钥、Token、密码、私钥不进入记忆、提示词日志或索引。
- 用户可以查看、修改和遗忘；导出、过期与批量删除须各自完成 API 和验收后再开放。
- 记忆内容仍是不可信数据，不能提升为系统指令或授予工具权限。

## 4. 每次请求的记忆投影

读取点位于既有上下文 middleware 内：历史压缩之后、正式模型调用之前。每次正常调用、工具后续模型调用、审批/任务续接和容量超限恢复后的调用，都通过 Repository 重新读取两层开关与当前目录下的 `source_type=user` 记录；不在 run、graph 或 checkpoint 缓存记忆条目。

```text
真实聊天历史 / checkpoint
→ 原有压缩和预算计算
→ 重查当前文件夹、当前对话开关和手工记忆
→ 仅复制本次请求的最后一条用户消息，附带有界参考区
→ ModelRequest.override(messages=...) → 当前所选模型
```

- 不增加 system 消息，不改写固定系统前缀或工具定义；参考区声明记忆可能过时，当前请求优先，不能据此执行新任务或扩大工具权限。
- 只取同工作区、同主体、同文件夹 ID/规范化路径的记录；最多检查 100 条，偏好/约束优先，再按最近修改排序。这是简单有界选择，不是相关性检索，也不扫描旧聊天或工作区文件。
- 复用 token 估算器。参考区至多使用可用输入预算的 5%、1500 tokens 和请求剩余空间中的最小值，额外保留格式余量；只选完整条目，不截断约束。再核对完整请求，装不下时省略记忆，不为记忆挤掉当前用户输入。
- `request.state`、消息表和 checkpoint 中的用户原文不修改。超限恢复仍压缩真实历史，然后重新读取记忆，不把第一次调用的参考区带入摘要或后续重试。辅助摘要请求、直接 `/tool`、子 Agent 不独立读取记忆；父 Agent 自己生成的委派内容仍可能包含它使用过的信息。
- `context.updated.memory` 只包含所选 ID、数量、估算 token 和上限，不含条目原文；完整输入用量已包含记忆开销，不应再次相加。该记录只说明本次准备了哪些输入，不保证模型实际采纳。
- 关闭/修改/删除影响下一次重新组装的调用；正在执行的请求与 SDK 内部对同一已组装请求的传输重试无法撤回。模型生成的回复、工具参数或后续历史摘要仍可能引用记忆事实，因此不能承诺把既有会话恢复成“从未见过记忆”。

## 5. 未来资料检索（需求验证后）

```text
用户授权原文
→ 版本化保存
→ 受限切片/关键词或向量索引
→ 带来源和版本的检索结果
→ 在上下文预算内按需使用
```

先确认一个个人工作流确实需要检索，再评估成熟库/存储，不一次建设 DocumentStore、VectorStore、Retriever 多套抽象。单用户 SQLite 是当前默认，不预设 PostgreSQL/对象存储部署。

检索先过滤归属、已删除/过期/失效内容，再去重排序与限制预算。索引不可用要明确失败或仅在已提供的关键词路径降级，不能编造结果。返回原文引用，不把检索材料提升为可信系统指令。

## 6. 生命周期与验收

- 删除/修改原文应使相关摘要和索引失效；版本变化可重建，不保留不可清理的副本。
- 需要执行恢复的数据交给运行时检查点，产品记忆交给 Repository，不建立第二个执行事实来源。
- 删除权威数据与派生清理须有可审计结果，但不预设必须增加通用事务事件框架。
- 日志只记录必要来源数量、耗时和版本，不 dump 完整记忆或文档。

发布前仍须验收两层开关、目录隔离、条目修改/删除、请求/检查点分离、续接/重试重新读取和超预算省略行为；自动提取若继续实现，还须覆盖来源准确性、用户确认和注入攻击回归。具体测试与交付状态只在 [测试与验收](../../testing/TestPlan.md)、[交付路线与状态](../../project/Roadmap.md) 维护。
