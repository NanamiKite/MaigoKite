# 工具权限与执行安全

> **状态**：当前有效
> **架构版本**：v1
> **源码规则**：2026-10-12；后续定向验收与未覆盖分支见 [当前验收状态](../../project/Roadmap.md#当前验收状态)，不将整份矩阵都视为未测试或全部通过。
> **权威范围**：工具风险等级、权限模式、审批与 hard-deny

系统级认证、凭证与网络安全见 [安全边界](../../ops-security/Security.md)。

## 1. 分层

```text
API 资源归属检查                  Python ToolPolicy
谁能访问哪个 Workspace 资源       Agent 能否执行具体能力与参数
```

两层都必须通过。API 资源归属检查的允许结果不能替代 ToolPolicy。

## 2. 风险等级

| 等级 | 含义 | 基础示例 |
|---|---|---|
| L1 | 无副作用读取 | 工作区内读取、glob、grep |
| L2 | 可恢复的低风险状态修改 | todo、短时等待、本地临时状态 |
| L3 | 外部交互或受限命令 | web search/fetch、受限 shell |
| L4 | 持久化写入 | 工作区文件写入、批量编辑 |
| L5 | 重大或难以恢复的影响 | 大范围删除、发布、发送外部消息、系统变更 |

等级是基础风险，不是最终决定。参数、路径、数据敏感度和部署策略可以提升等级或触发 hard deny。

## 3. 权限模式

| 用户档位 | 自动执行 | 请求批准 |
|---|---|---|
| 只读 `read_only` | 工作区内无副作用读取与搜索 | 编辑、命令、联网及其他副作用操作 |
| 工作区内修改 `workspace`（默认） | 工作区读取、低风险状态、文件编辑、真实沙箱内的普通命令 | 越界、命令联网、显式升级和敏感操作 |
| 完全访问 `danger_full_access` | 已启用工具直接执行，命令不使用工作区沙箱；不因 L5 逐项询问 | 不进行权限审批；仍受工具禁用、显式部署限制和操作系统权限约束 |

说明：

- `workspace` 的普通命令不再靠解释器白名单实现隔离。复用 bubblewrap 限定文件系统与网络，显式删除、修改权限等命令仍要求批准。命令识别不是完整的副作用分析，不能识别脚本中所有破坏行为。
- `danger_full_access` 必须通过新的明确模式值选择，不等于取得管理员权限，不启用原本停用的工具，也不取消工具本身的参数、会话归属、超时等约束。
- 旧 `full_access / auto` 统一解释为兼容值 `workspace_auto`：保留工作区边界及旧 L1–L4 自动范围，L5 仍需批准。启动时规范化历史会话，旧设置/YAML/客户端请求同样不会升级成无限制权限。前端须将兼容值显示为“旧版受限自动”，不能再标为“完全访问”。
- 窄授权不覆盖 L5；完全访问是单独、显式的执行模式，而不是永久 L5 授权记录。
- L1–L5 是服务端风险模型，不作为普通用户需要逐工具调节的设置项。

个人版权限配置只有 `default_mode`，会话使用自己的 `permission_mode`。后端不再保存或传递逐工具可调风险矩阵，也没有独立的内存 grant/scope 权限存储。历史数据库中的 `tool_levels` 被忽略，下次保存该设置时清除；已有风险标签和审批审计保留。

`read_only` 允许用户对具体写入批准。Linux、Windows 的受限搜索统一使用固定可信 ripgrep 与校验后的只读内容快照，不依赖命令沙箱，也不是通用进程隔离。是否启用工具和是否允许调用仍是独立边界。没有独立审核模型，不注册“帮我批准”，也不增加调用模型判断风险的隐性成本。借鉴 [DSH 基础预设](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/interaction/permission-presets/src/index.ts) 的沙箱/审批分离，不移植其插件框架或实验 Auto review。

## 4. 基础工具映射

| 工具能力 | 基础等级 | 动态规则 |
|---|---|---|
| file_read/glob/grep | L1 | 工作区外路径升为 L5，受限模式需单次审批；敏感路径在受限模式拒绝 |
| todo_write/sleep | L2 | 超额资源占用可拒绝 |
| web_search/web_fetch | L3 | 携带敏感凭证或禁止域名时拒绝 |
| bash | L3 | 按命令、目录和副作用提升至 L4/L5/hard deny |
| file_write/file_edit | L4 | 工作区外升为 L5，需要精确参数单次审批；完全访问无需审批 |
| external_send/publish | L5 | 必须展示接收方和内容预览 |

技能声明的是 capability 请求。最终等级由受信 ToolPolicy 根据能力和参数决定。未知能力默认拒绝。

## 5. 决策输入与结果

```text
Python API：验证主体能访问工作区
ToolRegistry：工具存在且当前启用，校验 schema
PermissionManager.evaluate(tool_name, arguments, approved, risk_override, mode)
    → allow | approval_required | deny
```

顺序：

1. Schema 校验并规范化参数。
2. 解析实际资源范围和副作用。
3. 检查工作区访问与能力授权。
4. 检查 hard-deny。
5. 计算有效风险等级。
6. 应用模式与已验证的一次性审批。`risk_override` 只来自受信工具/MCP 注册元数据，不来自客户端或工作区设置。
7. 校验可复用审批回执，生成仅由服务端持有的 `sandbox_mode / allow_network` 执行快照；不新增 Grant 表或权限框架。
8. 执行或创建审批。

## 6. 硬禁止

所有模式都拒绝未启用/未知工具、不合法参数、违反显式部署 allowlist 或 blocked_patterns 的调用。普通模式额外拒绝已识别的凭证路径、直接写入 `.git` 元数据及少量明显破坏系统的命令；单次人工批准不能覆盖这些拒绝。完全访问不保留这套工作区保护，否则名称会与行为不符。

受限命令通过 `sandbox_permissions=require_escalated` 请求单次沙箱外执行，或通过 `network_access=true` 仅请求网络；参数只是请求，不是授权。普通模式下都必须审批。Git 元数据在沙箱内只读，修改 Git 必须先提出明确升级请求。已明确禁用的操作仍不能借升级绕过。

当前宿主命令没有独立网络隔离后端，所以单次沙箱外命令还必须明确包含 `network_access=true` 并一起批准，否则不启动。只有 `network_access=true` 不会解除工作区文件隔离。完全访问模式已经显式包含宿主网络许可。越界 glob/grep 批准仅允许读取指定目录，继续使用受控只读搜索；不借批准获得任意宿主命令权限。该固定搜索程序不是 OS 沙箱，不宣称具有命令沙箱的网络隔离保证。

已知路径与命令规则只是确定性保护，不是完整敏感数据检测/DLP。任意代码在允许目录内的副作用不能只靠字符串匹配可靠识别。

## 7. 审批

审批必须绑定：

```text
principal_id
workspace_id
task_id
tool_call_id
capability
normalized_arguments_hash
resource_scope
risk_level
expires_at
version
```

- 参数或范围变化后审批失效。
- 每份具体调用审批只能消费一次；可选窄授权回执见下文。
- 过期、拒绝和重复提交必须有确定结果。
- UI 显示能力、目标、参数摘要、副作用、凭证与网络范围。
- 审批与任务/工具调用状态在同一事务中更新。
- 决定只接受仍等待审批的任务，不能用遗留 pending 记录重新激活已结束任务。
- `allow` 恢复可能调用模型，先准备凭证，再消费审批；LangGraph 路径继续使用原生 HITL 恢复。
- `deny` 仅拒绝本次操作，不创建授权、不取消整轮。拒绝、单项工具状态与审计同事务提交；其他操作保持原权限要求。批次逐项审阅结束后，LangGraph 原生 `reject` 将未执行结果和 note 返回模型，让它继续允许部分或说明限制，不得重试/绕过拒绝。
- 拒绝本身不依赖可用模型；Python API 尽力恢复模型凭证而不启动被拒绝的 MCP，续接无法进行时另行报告 `task.failed`。已拒绝的调用在工具边界重放时也不得执行。`cancel` 才终止整轮、关闭剩余审批并等待运行清理；历史已取消回合不自动恢复。

### 窄范围复用

- 决定接口支持 `scope=once|task|session|session_public_web`，默认 `once`。客户端只能选择服务端 `allowed_scopes` 中的值，不能提交自定义授权规则。
- 复用范围由策略生成：文件写入/编辑分别绑定同一父目录（不含子目录）；命令绑定完全一致的 argv、工作目录；网页读取/打开绑定 origin；搜索绑定服务提供方。
- 同时绑定主体、工作区、会话、模式和策略版本；L5、MCP、不透明外部操作和沙箱外命令不提供复用。
- `task` 限当前活跃任务；`session` 限当前会话。可复用授权最多 8 小时，不是永久白名单，可通过授权撤销接口提前结束。
- `session_public_web` 是单独的显式选项“本会话搜索和公共网页读取”：仅面向 L3 的内置 `web_search / web_fetch`，允许本会话使用已配置的搜索服务及读取不同公共站点。仍执行网页地址和每次重定向的公网校验，不包括 Browser、MCP、命令联网、登录态、上传或提交操作。搜索服务会收到查询内容，网站会收到访问请求；它不是数据防泄露机制。
- 旧 `task / session` 授权继续绑定原搜索服务或 origin，不自动升级成公共网页授权。审批卡片明确区分搜索服务/站点范围，快照刷新不重置未提交选择；操作 ID/version 改变或原选择不再可用时才重置。
- 权限模式、目录、归档、工具选择及生效扩展变化撤销相关回执；每次工具调用重新查询，不依赖旧进程内存。只读子 Agent 不继承授权。
- 工具准入先等待串行锁并读取待处理输入/审批，再由 Repository 在同一锁内读取当前会话模式与有效窄授权，避免新模式配上已撤销的旧回执。固定模型入口也读取持久会话模式，不沿用启动时快照。已准入的调用保留自己的权限副本；同批后续调用重新准入，需要审批则走原生 HITL。降级不回滚或强杀已经开始的操作，停止运行仍使用取消接口。
- 回执字段保存在现有 `approvals`；LangGraph checkpoint 仍是暂停/恢复的唯一执行事实来源。撤销影响后续调用，不撤销已开始的副作用或已批准的原始单次调用。

## 8. 沙箱与当前限制

- 内置工具使用路径、进程和网络策略限制。
- `exec_command` 的 `shell=direct` 不经过 shell 展开；`auto` 在 Windows 优先选择 PowerShell 7、缺失时选择 Windows PowerShell 5.1，其他平台保持 direct。显式 `pwsh` / `powershell` 不互相回退。PowerShell 脚本整体交给对应解释器，不用 POSIX `shlex` 拆分。
- Shell 选择在审批前归一化，与原始脚本一起进入已有审批参数/hash；传输用的 Base64 不替换审计正文。PowerShell 脚本按 L5 不透明操作处理，非完全访问模式需单次批准，不生成任务/会话复用授权。已配置的命令前缀白名单对脚本只允许全文匹配，不因开头命令允许而放行后续语句；工作目录仍校验路径。产品不声称能静态识别脚本中的所有敏感访问。
- Linux 复用 bubblewrap，只挂载只读运行库和指定工作区，受限命令默认不共享网络。启动参数显式要求 user namespace、禁止嵌套 user namespace、去除全部 capabilities；安装版本或系统不支持时拒绝受限执行，不删除保护参数重试。可用性探测与实际执行使用相同隔离选项，断网探测不再带 `--share-net`。命令启动前递归遮蔽已知凭证路径，嵌套 `.git` 只读，不遍历符号链接。扫描遇到保护项符号链接、权限错误、超过 10 万项/5 秒或挂载参数预算时拒绝启动。此处仅是已存在路径的保护，不检测内容、改名凭证、硬链接或并发宿主修改；不能称为完整 DLP。PowerShell 安装位置不在挂载范围时，受限执行同样拒绝，不自动扩大挂载。
- 受限进程沙箱不可用时返回 `SANDBOX_UNAVAILABLE`，区分缺少 bubblewrap、不支持所需参数、系统拒绝、启动失败和探测超时；不回退为普通宿主命令。Windows 已接可选 SRT 原生后端，默认关闭、alpha 且待实机验收，见下节；macOS 后端未接入。`file_read` 等进程内工具继续使用产品路径校验，`glob/grep` 的受控路径不受命令沙箱可用性阻塞。
- 受限 `glob/grep` 只运行工作区及搜索目录之外、绝对 PATH 下的可信 ripgrep；模型不能提供程序、shell、额外 argv 或环境。固定参数禁用外部配置、符号链接跟随及父目录/全局 ignore，目录内 ignore/glob 规则仍由 ripgrep 处理。文件内容通过句柄逐层打开，拒绝链接、重解析点及已知敏感路径，再制作有限临时快照。文件名发现仍访问实时目录和目录内 ignore 文件；这不是完整 OS 隔离或 DLP，不防御被替换的可信程序、硬链接别名或所有并发宿主修改。限制及清理见[配置指南](../../user-guide/Configuration.md#工作区工具)。
- 工作区仍不得配置为文件系统根目录。单次已批准的显式升级命令、以及 `danger_full_access` 模式使用宿主 argv 执行，仍保留输出限制、取消、超时和进程清理。
- Linux 受限命令可由启动配置显式添加可信工具链只读目录，不从 PATH 自动扩大挂载范围；新增目录仍经过敏感路径扫描，不允许整个用户目录、默认私有数据目录或系统特殊目录。可写工作区内的包缓存按工作区复用，HOME 仍临时隔离；只读模式不持久化缓存。详情见[工具链与缓存](../../user-guide/Configuration.md#linux-命令工具链与缓存)。不改变现有审批、越界参数判断或 `.git` 只读规则。
- 越界文件操作只有匹配审批/窄授权或显式完全访问才执行；浏览器文件操作同时校验页面 URL 和会话归属。完全访问不增加 Browser/MCP/子 Agent 的新功能。
- MCP 工具结果是不可信输入，但当前 **MCP Server 程序必须由部署者信任**：它由官方 SDK 直接启动，拥有宿主用户权限；最小环境、cwd 和审批不构成该进程的 OS 隔离。不得把工具结果不可信与进程已隔离混为一谈。
- 本地技能只读取声明内容，不获得独立进程权限；目标 SkillGrant 尚未交付，当前 MCP 信任与环境来自部署配置。
- 命令与 MCP 子进程只继承各自允许的环境；这不代表 Playwright driver 和浏览器父进程已获得同样的宿主环境/权限隔离。Chromium 临时与持久化 profile 启动均启用其原生沙箱，不自动回退 `--no-sandbox`。
- 超时和取消应覆盖所属进程及后代，但当前 MCP 和同步线程存在限制；实际范围见 [智能体运行时设计](../../design/AgentRuntime.md)，不把目标要求当作已完成。
- Windows 宿主命令停止复用系统 `taskkill /PID <owned-pid> /T /F` 并等待退出，GUI 停止与执行超时/取消共用该清理回调。清理失败不假报成功。宿主路径不是 Windows Job Object 隔离，不能保证拦住已脱离或父进程已先退出的后台任务；受限路径另由下节 SRT 管理 Job 与 ACL，不提供后台进程托管能力。
- 创建子进程期间收到取消时，等待取得该子进程句柄再停止并回收；POSIX 正常退出也清理原进程组的剩余后代。它不保证收回主动脱离进程组的宿主进程；Linux 受限执行另由 bubblewrap 的 PID namespace 管理后代。
- 墙钟超时与预览限制继续保留。stdout/stderr 由后端管道捕获，单次合计最多保存 8 MiB，超限停止并等待清理；不限制命令直接写文件或历史日志累计。Linux 可选 `tools.command_limits` 通过 util-linux `prlimit` 落实每进程 CPU/虚拟地址空间软硬上限，缺少后端则失败；默认零表示不额外限制。它不是 RSS/cgroup/Job Object 的进程树总配额，`cpu_memory_limits` 仍为 false；Windows 非零 rlimit 配置明确不支持。详见[命令资源限制](../../user-guide/Configuration.md#命令资源限制)。
- Windows 文件参数在路径规范化前拒绝盘符相对路径（`C:foo`）、缺盘符根路径、设备路径、NTFS alternate data streams、保留名称及尾随点/空格；沿用 Python 标准库的保留名称规则。`.git` 大小写变体不能绕过文件写入策略，路径白名单用 pathlib 比较目录层级。已有 API 目录句柄保护保留；这些参数检查不是任意 PowerShell 代码的 OS 沙箱，也不消除进程内文件工具的所有 TOCTOU 风险。

### Windows 原生后端（可选 alpha，待验收）

复用 [Anthropic Sandbox Runtime 0.0.79](https://github.com/anthropics/sandbox-runtime/tree/v0.0.79) 的公开 SDK、专用账户、受限 Token、ACL、WFP 与 Job，不要求 WSL，不自研 Win32 安全机制。Python 继续持有命令生命周期，单次 Node 桥接持有一个 SRT session；现有 PermissionPolicy/审批不变。启动依赖、安装和启用步骤集中在 [配置指南](../../user-guide/Configuration.md#windows-原生命令沙箱)。

- 默认关闭；普通 setup 只下载锁定依赖，账户/防火墙安装需要单独的确认参数与 UAC。每次运行由 SDK 验证 WFP，失败不静默降为宿主执行。
- 工作区可写/只读映射为临时 ACL，已知敏感项拒绝读取、Git 元数据拒绝写入；拒绝 UNC/junction 工作区。同一用户的 MaigoKite 实例串行运行，避免共享 SID 下的授权叠加，但不隔离其他用户或其他 SRT 客户端。
- 上游允许系统 DNS，公开可读路径也不是工作区外不可见。代理令牌/共享账户有跨客户端限制；不承诺完全断网、完整 DLP 或等同 Linux 挂载边界。
- 停止先请求关闭 broker/Job，再等 ACL 回收回执；超时或清理失败明确报错。强杀恢复依赖上游，不重新实现 ACL journal。GUI 不暴露桥接控制管道，当前 Windows 沙箱不支持交互 stdin。
- 普通 `glob/grep`（包括只读子 Agent）继续使用可信 ripgrep 的受控只读搜索，不要求开启这个可选后端。MCP/浏览器/文件工具仍各自遵循上文边界。

本批只接源码并人工核对，未运行测试、安装账户/防火墙或进行 Windows 实机验证；不能据此宣布稳定 Windows 沙箱交付。
