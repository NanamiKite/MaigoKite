# 本地技能与扩展边界

> 权威范围：当前 SKILL.md 格式、加载、使用与未来分发门槛。
> MCP 协议/进程见 [MCP](../mcp/mcp-integration.md)，权限见 [工具权限](../security/tool-permission.md)。

## 1. 当前是声明内容，不是插件平台

核心服务从配置目录扫描 `SKILL.md`，也加载保存在现有产品数据库中的个人 Skill 指令；两者复用 `SkillRegistry.parse_content`，检查大小和元数据，通过 `skill list/read` 提供给模型。侧栏“扩展 → Skills”支持导入单个 Markdown、编辑、启停和移除托管指令，以及设置/重扫本地目录。

保存只更改期望配置，点击“应用并检查连接”才替换空闲 Runtime 的工具目录。正在执行、等待审批或回答的任务会阻止应用，不为刷新引入第二套运行时。2026-10-15 真实 Core 验收已覆盖托管 Skill 保存/应用、正文读取，以及扩展应用失败回退和生效配置重启加载；扩展设置 GUI、目录扫描超限/取消等不在本次通过范围，见 [当前验收状态](../../project/Roadmap.md#当前验收状态)。

Core 重启加载上次生效配置，不自动应用尚未生效的编辑；目录文件仍会重新扫描，不是不可变内容快照。“恢复已有连接”只恢复该配置的 MCP，复用当前已加载 Skill，不借恢复审批之机更换技能目录。

- 当前支持 `instruction` 与 `workflow` 两个 kind，均不执行包内代码；workflow 是流程说明，不是持久 DAG。
- 内置工具是受信内置代码，不通过第三方技能包注册。
- 受信可执行扩展通过个人扩展配置的 stdio MCP Server，不通过 SKILL.md entrypoint。
- LangGraph 路径已接声明式 skill 读取；目录摘要进入稳定前缀，正文按需加载。可调用能力仍受已迁工具与 PermissionPolicy 限制，见 [智能体运行时设计](../../design/AgentRuntime.md)。

## 2. 当前文件格式

```markdown
---
name: research-brief
description: 生成带来源的研究简报。
version: 1.0.0
kind: instruction
---
明确目标和输入；读取一手来源，区分事实与推断；
输出带引用的简报，遇到权限或资料缺口时停止并说明。
```

当前 description 与正文不能为空；版本未写时默认 `1.0.0`，kind 未写时默认 `instruction`，name 可从目录名获得。可选 `parameters_schema` 必须是对象；这些元数据不是自动执行协议。实际合法名称/大小与路径限制以 `skill_registry.py` 为准。

UI 导入/编辑时须写明 `name`，并与编辑器的名称一致；单个文件上限 256 KiB，支持 UTF-8 BOM/CRLF。托管内容保存在 `workspace_settings.extensions.config.skills`，不是磁盘上新建的目录；`managed:<name>/SKILL.md` 是来源标记，不能用于读取相邻资产。需要引用已有文件的技能应使用目录扫描，而非只导入 Markdown。

目录来源只读，不通过此页编辑或删除原文件；启停按名称保存。托管 Skill 与目录 Skill 同名时不静默覆盖，两者均不启用并报告冲突。移除托管 Skill 删除数据库中的配置内容；移除扫描目录不会删除目录或包内资产，下一次应用后不再加载。

正文应说明适用/不适用条件、输入/交付物、步骤、停止与失败处理、依赖能力。目录描述应短；不要把全文塞入固定提示词。

技能不包含凭证、隐藏系统提示、索取隐藏思维链或绕过权限的要求。声明“需要某工具”仅表示依赖，不表示该工具已安装、已迁移或获批。

## 3. 安全与资源

读取内容按不可信上下文处理，权限由服务端规范化参数和策略决定。技能不改变 hard-deny，不允许扩大文件、网络、Shell 或敏感凭证范围。

目录扫描通过标准库 `asyncio.to_thread` 在私有 SkillRegistry 中完成，不阻塞 Core 主事件循环，也不从工作线程修改共享目录。单次扫描预算为：

- 最多 20000 个目录/文件条目、512 个候选 SKILL.md。
- 累计最多读取 8 MiB，协作式时限为 10 秒。
- 单文件最多读取 256 KiB + 1 字节，再校验大小。

扫描跳过 `.git / .venv / venv / node_modules / __pycache__ / dist / build`，不递归目录符号链接，也不读取指向扫描根之外的文件、管道、设备等非普通文件。

超出总预算时丢弃本次磁盘扫描的部分结果并显示错误，托管 Markdown 仍单独加载；不是静默接受前半份目录。取消会通知工作线程停止，并等待它收尾。预算在文件系统调用之间检查，不是硬实时保证：`os.walk` 的单次目录枚举、网络盘/磁盘读取无法被 Python 强制中断，不实现线程杀死机制。大目录应改为具体技能目录；扫描与取消边界本轮仅源码检查，未运行验收。

MCP 子进程生命周期独立于技能内容，仍由核心服务管理；不要因为同属“扩展”统一成新的插件生命周期、DI 或能力框架。

## 4. 未交付的扩展分发

当前已有“扩展 → 导入工作流”，接收本机生成的 MCP + Skill 联合 JSON。它只复用现有设置 API 保存声明，不安装依赖、启动服务或自动应用；同名覆盖和工具范围变化需要确认，扫描目录同名冲突仍须解决。天线包的 `connect` 是这一入口的使用方，不构成新的 Skill 包管理器。

当前的 Markdown 导入不等于技能包安装。仍没有 Git/ZIP/远程安装、签名、依赖解析、不可变 SkillVersion、工作区 Grant 或升级/回滚。移除先前完整目标 Manifest/状态机，避免其被当作当前格式。

只有用户确需分享/安装个人定制流程时才调查成熟分发实现，并比较复用成本。不为小规模本地文件新增注册中心、发布者平台或包管理器。

若确需执行型分发，最低约束为：

- 安装前验证来源、摘要值、内容与能力，失败不执行入口。
- 入口用 command/args 而非 shell 字符串；依赖确定且不得隐式扩大权限。
- 用户配置与不可变内容分离，只存凭证引用；版本更新不覆盖用户配置。
- 能力增加要重新批准，撤销凭证不因回滚恢复。
- 停用/卸载阻止新调用并等待或取消活动调用，停止所属进程并保留必要审计。
- 不混淆包版本、授权和运行进程状态。

这些是未来安全门槛，不是现有 Schema/API；只有真实需求、后端闭环与测试后才新增格式，届时在本页维护唯一规范。
