# 前端与桌面交互设计

> 本文说明 Vue 页面、客户端状态、Electron 安全和用户交互。
> API 字段见 [API 设计](API.md)，权限矩阵见 [工具权限](../agent-capabilities/security/tool-permission.md)，运行机制见 [智能体运行时设计](AgentRuntime.md)。

## 1. 分层与当前目录

```text
Views / Feature Components
→ Pinia Stores / Composables
→ 集中 API / Event Client
→ Python FastAPI
```

页面组合界面，状态仓库保存客户端投影而非服务端状态机；业务请求携带工作区，所有端点集中封装。实际代码在 `web/src/views / components / stores / composables / api / types`，Electron 在 `web/src/electron`。不为架构整洁预建 features/events/supervisor 等空目录。

## 3. 设置与文件交互

### 模型

配置行 → 单一编辑器 → 可搜索模型目录。同一时间只展开一个编辑器；默认只显示服务摘要、凭证状态与默认标记。

添加时使用协议/地址预设，不承诺具体模型。目录读取使用当前草稿，选择仅写入草稿；测试也不保存。草稿变化使测试结果失效。目录失败仍可手输准确 ID，普通用户不维护采样温度等服务参数。

API 密钥不回显，模型提供方/端点变化不得复用旧凭证。字段与发现协议见 [API](API.md) 和 [模型接入](../agent-capabilities/models/model-routing.md)。输入框附近可选择会话模型、模型支持的思考设置与执行模式，不改变工作区默认设置。思考能力由 Core 返回，不按模型名称猜测，也不等同于输出预算。

### 工具选择

“设置 → 工具”按实际注册目录显示启用状态；工具可见性与审批权限独立，启用不代表免审批。启动配置的停用列表不能由界面放宽。接口与生效范围见 API 和配置指南，不复制工具清单。

### 权限与运行状态

用户只选三个稳定权限模式，不编辑 L1–L5。审批展示工具、规范化参数、目标和副作用、风险/有效期；提交后等待服务端确认，不本地标记成功，也不添加尚无服务支持的永久授权按钮。

审批选项以操作 ID 和版本为准，定时快照刷新不重置用户尚未提交的选择；服务端不再允许原选择时才退回单次。新增“本会话搜索和公共网页读取”只覆盖内置搜索及公共网页读取，不包含浏览器、MCP、命令、登录、提交或上传；旧授权仍保留原范围。

安全确认使用独立 `value` 提交决策，`label` 只用于显示。会话默认标题也只是显示文字：新建时发送空标题，由服务端 `title_source` 决定是否自动命名，不比较“新对话”等翻译文本。API 错误优先按已知错误码和安全参数翻译，未知码保留服务端安全提示，不从中文错误文案猜类型。

「安全」页签单独管理审查配置及独立决策模型凭证。配置接口和 GUI 测试已完成，运行时在主模型调用前审查新增提示词；高风险结果复用结构化提问/恢复链路。字段、凭证规则和搜索定位见 [API 设计](API.md#36-设置模型和凭证引用)，界面不提供单独的连接测试按钮。审查模型仍有已知误判和崩溃，配置测试通过不代表能可靠识别所有风险，具体问题见 [路线图](../project/Roadmap.md#当前验收状态)。

运行状态只显示服务返回的真实路径、单一 Python 后端状态、版本与生效范围；不得根据浏览器/Node 猜路径。当前页面不编辑启动参数，也不宣称检测到外部 YAML 的“待重启变化”。凭证存储等说明可置于帮助/详情，不在主要界面持续展示工程说明。

Electron 的运行状态另提供图形加速开关和实际 GPU 特性状态，Web 不显示此入口。偏好在主进程 ready 前应用，修改后需从托盘退出再重开；检测尚未完成时显示等待，不能将开关已开启显示成硬件加速已生效。

### 工作区文件

按目录懒加载，忽略依赖/虚拟环境/构建目录；文本预览只读，不默认读取二进制。Git 状态先查一次，选中文件再加载差异，不隐含暂存/回滚操作。大小限制和路径约束以 API 为准，渲染进程不得自行访问文件系统。

文件树展开状态仅由文件树 composable 提供，组件不再维护另一份展开状态。列表、预览和差异请求分别反馈错误；切换选择或卸载后不应用旧请求结果。工作抽屉嵌入文件树时不沿用旧侧栏折叠状态和重复的标签导航。

文件预览可下载当前文件，通过既有认证读取 Blob，不将带凭证 URL 交给浏览器；ZIP 不要求能文本预览，也不在前端解压。天线候选包的导入完成与工程状态分别展示，不能把文件成功下载显示成设计通过。

Git 变更查询由 `useWorkspaceChanges` 统一管理。面板重新打开、窗口聚焦、连接恢复及相关文件/任务事件会触发刷新，连续请求合并；隐藏或切换工作区后取消旧请求。列表显示当前 Git 未提交状态，不把执行小结中的历史文件操作混入其中。这项自动刷新尚需真实 Git/GUI 回归。

## 4. 回答、活动与错误

- 用户消息/助手回答是聊天记录；公开过程、工具/审批活动是另一类对象，不写进输入框或混进回答气泡。
- 活动按任务/sequence 排序，可折叠；参数和原始结果在二级详情。子 Agent 的实际能力以 [运行时设计](AgentRuntime.md#7-技能子任务与工作流边界) 为准，不能仅凭事件名推断编排能力。
- `message.*` 更新回答；`reasoning.* / tool.* / approval.*` 更新活动。界面不猜测文本类型，不请求或展示隐藏思维链。
- tool.failed 显示稳定错误码和简短 user_hint；只对已有设置页提供受限内部链接，不根据模型任意 URL 导航。
- 输入组件仅负责编辑/发送。运行中显示停止按钮与 aria-busy，会话切换不共享全局发送锁；停止后等待真实服务端终态。
- 聊天和任务抽屉共用客户端停止入口：提交前暂停该会话待发队列，提交期间禁用重复停止，失败可见；排队消息可取回编辑，保留当前输入草稿。此入口只协调 UI/API，不是另一个取消运行时。
- Markdown 规范化只处理确认的重复编码和结构转义，保留代码、正则、公式的反斜杠；HTML 清洗后入 DOM，禁脚本、事件属性、表单和主动加载媒体。

## 5. 客户端投影与重连

当前 session/settings/layout/memory 和只读能力清单状态仓库按功能分工。没有服务支持时不建空 SkillGrant、Inspector 或调度器状态仓库。

UI 在读取消息、任务和审批快照之前开始缓冲事件，应用快照后合并缓冲，并继续分页读取历史。聊天与审批实时流保留 Core 的 event ID，前端按此去重；历史游标只随持久历史读取推进，不能用一个较大的实时序号证明此前没有遗漏。`message.completed` 的持久消息 ID 替换流式占位。正常聊天、历史重连和界面刷新已有测试；快照并发、截断和投影异常仍需验证。详细协议见 [API 设计](API.md)。

网络断开不取消主机任务，UI 不自行推断完成。无幂等保障的命令不自动重试，重复点击须等待/禁用或依赖已存在的版本校验，不假定已有通用幂等键。

### 首版 UI 报告的接口边界（2026-10-10）

本节保留首版 UI 的约束，不再用当时缺少的接口描述当前能力。后续已接入问答、审批理由与窄范围授权、逐步插话和进程管理；当前契约见 [API](API.md)，验证范围见 [交付路线与状态](../project/Roadmap.md)。仍须遵守：

- 审批使用 `allow/deny + version`，授权范围由服务端 `allowed_scopes` 决定。不能将 `allow_session` 静默降格成单次 `allow`，也不能丢弃驳回理由。HTTP 202 只表示请求已接受，UI 仍等待服务端审批和任务状态。
- 任务取消和进程停止是不同操作；进程接口只管理 Core 持有的真实命令句柄，不提供任意后台进程管理。文件/Diff 查询不提供回合回滚、逐文件接受/撤销或任意步骤重试。
- 逐步插话与下一回合待发消息必须区分。后者按会话与当前 task 绑定，允许撤回/编辑；`waiting_approval`、断线、`message.completed` 都不触发发送。取消、失败、中断后保留待发草稿，等待用户再次确认，不自动启动下一回合。插话消费时机以 API 的回执为准。
- 发送排队消息前核对当前任务终态及会话归属；切换会话不能串发，重连回放不能重复消费。没有服务端消息幂等保证时，网络失败不得自动重发。
- Mock 可以回放完整设计流程，但仅用于显式开发演示，持续标识“演示模式”；与真实服务的请求/事件/状态隔离，不连接真实 Electron 副作用入口，禁止真实 API 失败后自动回退 Mock。Mock 中的会话批准、问答、回滚等不计入产品完成度。

新增交互逐项核对产品语义、权限、持久化和接口，不为界面预留操作另建通用交互框架。

## 6. Electron 边界

当前 BrowserWindow 使用 `contextIsolation=true / nodeIntegration=false / sandbox=true / webSecurity=true`。导航和新窗口受控，渲染进程不获任意 Node、Shell 或文件权限。

当前预加载白名单包含运行状态/错误订阅、窗口控制、外观、托盘状态、通知、工作区路径打开与速记；真实 IPC 在主进程校验窗口来源和参数。renderer 类型由实际 preload 对象派生，不再维护一份超前的方法承诺。业务请求仍统一走 Python API；这些接线不代表 runtime bundling 或桌面发布已验收。

Electron 持有自己启动的单个 Python 后端进程并协调关闭；启动、退出等待和平台差异见 [开发指南](../development/DevelopmentGuide.md)。源码中的生命周期处理不等于完整进程监督或跨平台安装验收。打包路径、签名和干净机器验收由 [构建与发布指南](../deployment/ReleaseGuide.md) 定义。

## 7. 性能与可访问性

- 高频拖拽/流式更新按 requestAnimationFrame 合并；持久化在交互结束时，不在 mousemove 同步写 localStorage。
- 长聊天使用 content-visibility 跳过屏外绘制；自动滚动只观察消息数/末条长度，避免全历史扫描。
- 大面积与重复卡片避免 backdrop-filter；实色/半透明和轻阴影保留一致视觉层次。
- 按 route name 复用页面，会话 ID 变化不重建整棵组件树；文件和差异按需读取。
- 弹窗关闭恢复焦点，关键操作键盘可用，允许暂停自动滚动。性能目标需要长会话实测，不以视觉效果代替指标。
- 命令面板与收件箱使用原生 modal dialog，不自建焦点陷阱；审批键不穿透弹层，Escape 优先关闭当前弹层或输入候选菜单。

Web 开发模式由 Vite 代理 Python API；构建版由 Python 同时提供页面和 API，Vite 不能独立提供业务。桌面构建与手机适配不在 Vue 业务代码复制第二套 API/状态。

## 8. 视觉设计覆盖范围

视觉方向、排版和组件表现见 [墨线 UI 设计](agent-ui-design.md)，行为与能力边界以本文件和当前 [API](API.md) 为准。会话批准、问答、插话和进程管理只能开放服务端支持的范围；回合撤销、任意执行节点分叉不能用聊天分岔或文件 Diff 代替。视觉原型/Mock 不构成实现或验收证据。
