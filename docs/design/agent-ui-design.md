# 个人 Agent 前端设计文档 · 「墨线 Inkline」

> 核心隐喻：对话是工作纸上的正文，执行过程沉成页边的墨线。常用交互复用成熟产品的惯例，不为视觉身份发明新的操作语义。
> 技术基线：Vue 3 + TS + Vite 5 · Pinia · Vue Router 4 · SCSS + CSS 变量 · Electron 28 · fetch + WebSocket（Go Gateway）。
> 2026-10-11：阶段 1–4 已验收；阶段 5+6 已完成本地页面收尾与质量检查，尚待用户验收。当前规范以第 1–7 节为准，第 8 节起保留各阶段历史证据。

---

## 1. 设计身份

| 维度 | 主流 Agent 的做法 | Inkline 的做法 |
| --- | --- | --- |
| 隐喻 | 聊天窗 / 终端 | 手账 + 行程线：对话是正文，Agent 的动作是页边的一条墨线 |
| 气质 | 冷灰科技感 | 宣纸白 / 松烟墨，强调色只用一种「石青」，暖、静、耐看 |
| 过程展示 | 一张张卡片往下堆 | 卡片折进**轨道（Rail）**，正文只留结论 |
| 状态感知 | 转圈 spinner | 一枚会变形的**脉点（Pulse）**，同时出现在标题栏和托盘 |
| 人机协作 | 每个会话里各自弹审批 | 当前对话**就地处理**；抽屉的**「等你处理」**页签汇总跨会话事项，失焦时保持系统提醒 |
| 桌面能力 | 网页搬进壳里 | 全局快捷键唤出**速记胶囊**、无边框窗口、托盘常驻 |
| 个人属性 | 无记忆界面 | **「它记得」**面板：Agent 的记忆、偏好、人设可以直接看和改 |

设计原则：
1. 正文只放结论，过程沉到页边。
2. 一眼知道它在干嘛，一键让它停。
3. 它是你的，不是租来的：可以命名、配色、看到它记住了什么。
4. 不用强调色堆层级，靠留白、字重、墨色深浅。

## 2. 视觉语言

### 2.1 色彩（CSS 变量，SCSS 只引用变量）

| Token | 宣纸（Light） | 松烟（Dark） | 用途 |
| --- | --- | --- | --- |
| `--paper` | `#F8F5EF` | `#141716` | Inkline 主画布 |
| `--paper-2` | `#F0ECE3` | `#1C211F` | 侧栏、次层纸面 |
| `--paper-3` | `#E7E1D6` | `#272E2B` | 压层、局部控件底色 |
| `--rule` | `#D9D5CA` | `#39423B` | 分隔线、轨道线 |
| `--ink` | `#252722` | `#F1EEE8` | Inkline 正文 |
| `--ink-2` | `#4E534B` | `#BCC3B8` | 次要正文、导航、标签、说明和状态 |
| `--ink-3` | `#62655C` | `#90998D` | 占位、时间戳和元信息；最深纸面仍 ≥ 4.5:1，与二级墨色保持区别 |
| `--accent`（石青） | `#2C6963` | `#8AB9A8` | Inkline 主按钮、运行中、焦点 |
| `--accent-soft` | `color-mix`，9% 强调色 | 同左 | 选中底色；hover / pressed / border 同样由令牌派生 |
| `--seal`（朱砂） | `#AC3E2B` | `#E17A62` | 仅用于危险操作和「驳回」印记；成功反馈用墨色和形状 |
| `--wait` | `#B07A1F` | `#D7A548` | 等待你 |

规则：页面上同时出现的饱和色不超过两种；`--seal` 只在需要你警惕的时候出现。
用户可以在设置里把 `--accent` 换成另外 5 种预设（黛蓝、竹青、赭石、藕荷、墨），这是「它是你的」的一部分。

### 2.2 字体
- 界面：`"Inter", "HarmonyOS Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif`
- 签名字体（只用在四处：空态问候、会话标题、回合小结标题、审批印记）：`"Source Han Serif SC", "Noto Serif SC", serif`。宋体用得少，才有辨识度。
- 代码：`"JetBrains Mono", "Cascadia Code", monospace`
- 字号比例尺：12 / 13 / 15 / 19 / 24 / 30 / 38 / 48。正文基准 15px、行高 1.7；技术信息 12–13px。外观设置提供小 / 标准 / 大三档（14 / 15 / 16.5px），不改变业务数据。

### 2.3 形状与质感
- 圆角：6（Chip）/ 10（卡片）/ 14（输入区）。比主流的大圆角更收敛，像纸的切角。
- 深度使用四级 elevation；抽屉使用 `--shadow-raised`，命令面板使用 `--shadow-float`，不为每个会话条目添加阴影。
- 画布噪点 0.022、工作纸 / 砚台 0.025，纹理位于正文下面；代码区不铺纸纹。设置可关闭。
- 按压、控件、面板、叙事分级使用 motion / ease 令牌；面板 240ms。动画只改变 transform / opacity，SVG 第一笔允许 stroke-dashoffset；不持续动画阴影、blur、filter 或布局尺寸。减少动态效果时降级为 80ms 短淡入。
- 所有控件统一 hover / focus-visible / pressed / disabled；`prefers-contrast: more` 加强边界和焦点，不改变信息角色。
- 欢迎纸面的进场动画在播放完成或首次获得焦点后永久落定，仅进入另一个空白对话时重置。不能用 `:focus-within` 反复切换动画；模型菜单等传送到页面顶层的弹层获得焦点时，不得重新播放纸面、问候、题记或输入框动画。减少动态效果时沿用同一落定规则。

### 2.4 选择与确认控件

- 单项选择统一使用 `InkSelect`：触发按钮与字段同层级，展开后使用纸面浮层、石青选中底色和勾选标记。浮层在原生 dialog 顶层定位，自动选择向上或向下展开，长列表独立滚动，避免被抽屉、表单和外层弹窗裁切。方向键、Home / End / PageUp / PageDown、输入文字定位、Enter / Space 选择、Esc 取消，关闭后沿用原生焦点回收。
- 现有 `Event.target.value` 处理函数由隐藏的 select 桥接，隐藏元素不提供系统菜单；字段校验、保存和审批接口不变。对话模型保留已有按提供商分组与搜索的 `ModelPicker`，只对齐浮层主题，不退化为普通列表。可信模型候选填写实际模型 ID，不使用配置记录 ID；手工输入继续保留。
- 聊天模型提供商标题支持折叠，弹层内采用有层级的模型树；搜索展开匹配组，清空搜索恢复手动折叠，重新打开时展开当前模型所在组。上/下遍历可见节点，Enter 选择模型或开合分组，空搜索时左右键开合；Alt+数字仅对应可见模型。不同服务名称、地址与协议继续独立分组，不合并凭证。
- 设置提供商卡借用原生 details/summary 的开合与键盘语义，自绘标记、背景与箭头；标题切换开合，「管理模型」独立编辑，折叠不影响默认模型或凭证。原生行为不等于系统默认外观。
- 鼠标悬停与键盘导航高亮分别处理，移开后不留下导航底色或阴影；真正选中仍保留勾选与强调色，键盘保留 focus-visible。统计柱状图的悬停预览随鼠标离开结束，点击选择仅保留底部细线，不用整列背景冒充悬停。
- 系统 `window.confirm` 改为 `InkConfirm`，复用原生 dialog 的焦点陷阱与 Esc 取消；危险操作使用朱砂确认按钮，默认聚焦取消，确认期间后台状态变化后仍复核操作目标与忙碌状态。
- 复选框保留原生输入与 checked / indeterminate / disabled 语义，外观由令牌控制。`InkNumber` 只装饰现有数字输入和加减按钮，min / max / step、键盘调整和数值校验仍由原生输入负责。
- 560×56 速记胶囊不展开下拉菜单，改为并排的「最近会话 / 新会话」目标按钮，避免菜单被独立窗口裁切。系统文件夹与文件选择器继续保留；本轮没有统一原生悬浮提示。

### 2.5 界面文案

- 页面只呈现操作、结果、必要帮助与风险；开发阶段、实现分工、协议生成方式、配置存储机制等放在项目文档，不写成常驻界面说明。
- 安全页的 JEV 布局沿用 InkSelect，选项用「消息对象 / 内嵌指令」；不常驻展示载荷字段路径、实测模型尺寸推荐或过时的 Runtime 开发状态。真实配置字段、服务不可用、风险后果及保存失败仍须保留。
- 字段标签和按钮已能说明的内容不再另起段落重复解释。确有必要的说明用简短用户语言，并进入中英文语言目录。
- 不用删除提示掩盖能力缺失：安全审查尚未参与对话时必须明确告知。权限后果、记忆发送范围、不可撤销影响、未知模型容量和失败原因仍需保留。
- 上下文仪表面向用户显示容量与用量，不显示内部路由分类；容量来源和测量数据继续保留在原有数据链路中。
- 对话模型切换标记放在首次使用新模型的用户消息上方，沿用任务事件中的实际模型信息。相同模型连续发送不重复标记，切回旧模型再次标记；补充输入不新建标记，初次选择不算切换。历史模型信息缺失时不推测，不用当前选择改写历史。

## 3. 布局

```
┌───────────────────────────────────────────────────────────────┐
│ ▥  MaigoKite                                         ─ □ ×   │ ← 桌面窗口栏
├──────────┬──────────────────────────────────────┬─────────────┤
│ 品牌区   │ 脉点 会话标题（宋体） 子 Agent ◐ 抽屉②│ 抽屉标题    │ ← 应用导航栏
│          ├──────────────────────────────────────┼─────────────┤
│ 侧栏     │  ┆                                   │ 抽屉        │
│ 240px    │  ○─ 翻了 3 个文件                    │ (按需滑出)  │
│          │  ┆   ┌─────────────────────────────┐ │ 变更 / 运行 │
│ ✎ 新页   │  ┆   │ 正文：Agent 的回答           │ │ / 计划 / 文件│
│ ⌕ 搜索   │  ●─ 跑了 pnpm build ✓             │ │             │
│          │  ┆   └─────────────────────────────┘ │             │
│ 今天     │  ◆ 回合小结 · 2m · 3 处改动          │             │
│ 本周     │                                      │             │
│ 更早     │  ┌───────── 砚台（输入区）──────────┐ │             │
│ 它记得 ✦ │  │                                  │ │             │
│ ⚙        │  └──────────────────────────────────┘ │             │
└──────────┴──────────────────────────────────────┴─────────────┘
```

- **桌面窗口栏**：`WindowBar` 独占最上方一行，横跨整个窗口，放侧栏开关、应用名和窗口控制；不放会话标题、子 Agent、主题或抽屉入口。保留 Electron 无边框窗口，拖动区域仅在这一层。窗口控制贴右边缘、全高直角，按压不位移，关闭键使用朱砂反馈；macOS 保留原生红绿灯并让出对应空间。高度使用 `--window-titlebar-height`（36px）。这里的应用名不是菜单，没有新增或仿制「应用 / 编辑」菜单功能。
- **应用导航栏**：现有 `TitleBar` 位于主内容列顶部，与侧栏品牌区并列，高度使用 `--titlebar-height`（44px），不再横跨侧栏和抽屉。脉点 + 宋体会话标题支持中间省略和双击重命名；子 Agent、主题和抽屉入口只在这一层，不再与窗口按钮同排。保留稳定的 `chat-session-actions` 挂载点，子 Agent 的数据、保存及隐藏条件不变。Web 版不显示桌面窗口栏，侧栏开关留在应用导航栏；两种模式都只保留一处开关和原有 Ctrl+B。没有独立待处理弹层。
- **子 Agent 默认值**：设置新增独立「子 Agent」页，保存新对话的派发上限（0 关闭）、并行数量与允许指定的模型。复用对话顶部的表单字段和现有校验，遵守服务能力声明；默认仍关闭，仅允许现有只读/搜索能力，不新增执行权限。默认值保存在当前客户端的 localStorage，同源窗口通过 storage 事件同步；非账户跨设备偏好。所有普通新建入口统一在创建请求中携带默认值，不覆盖已有或分岔对话。空白聊天顶部可临时覆盖，返回新建页时恢复默认值；已创建对话顶部仍只修改该对话并从新任务生效。不支持能力、保存失败或模型配置已移除时明确反馈，不静默启用或丢弃选择。
- **侧栏**：工作区 > 今天 / 本周 / 更早 > 会话。运行中的会话使用脉点；非当前会话的阻塞项使用等待菱形。底部保留「它记得」入口。`Ctrl+B` 收起。
- **工作区入口**：加号只用于添加文件夹；已有工作区在侧栏直接点击，收起态和工作纸中的入口展示名称/路径列表，不使用「切换已有工作区」下拉表单。本机 Web 使用目录浏览器，目录位置自动填充，支持上一级、用户目录、根目录、筛选和隐藏文件夹；单击选择、双击或 Enter 进入，也可点击行尾箭头进入，确认后沿用原文件夹登记接口。Electron 保留系统选择器。工作区名称可留空；选择不会移动已有对话。
- **工作区移除**：后添加的工作区在侧栏和选择列表均有删除入口。确认弹窗展示名称、路径和明确后果：文件不动、对话保留并移至默认目录；后续文件操作使用默认目录。等待审批、运行/清理中的任务或进程、最新可恢复任务会阻止删除。默认工作区不显示删除按钮。移除当前行后焦点回到可用工作区行，当前对话保持打开、归属改为默认工作区。
- **正文区**：最大宽度 720px，左侧留 48px 给轨道。
- **流式渲染**：实时正文仅由 Run store 按帧发布，持久消息在完成或快照恢复时更新。文本帧保留工具、审批与补充输入的引用；轨道投影按活动集合缓存，缩略图只测量已经挂载的内容，测量间隔至少 120ms。Markdown 继续使用现有解析器与消毒策略，长文本按 100–400ms 自适应节流，结束时立即刷新；流式前缀不挤占已完成消息的缓存。无待处理项时不安装待处理 DOM 观察器。本次未做交互或性能运行验收。
- **抽屉**：保留宽度拖拽与持久化；「等你处理」跨会话，变更 / 运行 / 计划 / 文件沿用现有上下文。`Ctrl+.` 打开，`Ctrl+J` 直接切到待处理页签。
- **运行定位**：每条运行标题旁保留独立的「定位到对话」图标按钮，不依赖卡片展开。点击展开前端折叠的历史并定位到对应用户消息开头，短暂墨色高亮；暂停自动跟随，窄屏关闭覆盖抽屉以露出目标，宽屏保留运行面板。目标尚未载入时按钮禁用并说明；重复点击仍可再次定位，不创建对话或子代理页签。高亮仅动画 opacity，减少动态效果时改为短淡入。
- **运行记录与子 Agent 页签**：运行条目以输入标题和真实状态作摘要，历史默认折叠、分批展开；展开后显示原输入、执行小结和操作明细。小结复用聊天中的文件预览、命令结果、审批记录与失败详情，不再维护第二套统计。子 Agent 入口归属父运行，点击在「运行」面板内部打开独立页签，展示委派任务、实际模型、模型公开提供的思考/回复和只读工具结果；不新建工作区对话，不提供额外发送入口。关闭页签仅关闭视图，切换工作区对话后清空当前打开的子页签；切换抽屉页签保留视图。记录通过父任务现有事件历史恢复，旧记录缺失的过程不补造。页签支持左右方向键、Home/End 与 Delete 关闭；同一父运行和子 Agent 只打开一个页签。
- **分隔条**：左右侧栏宽度、文件树 / 文件预览高度、变更列表 / diff 高度复用现有 `ResizeHandle`，内容区和分隔条明确设置 Electron `no-drag`。鼠标使用原生 `mousedown / mousemove / mouseup`；触摸和手写笔保留 Pointer Events。移动和释放由文档捕获阶段监听，不以指针捕获成功为前提；释放、按钮松开、失焦、窗口隐藏、窗口尺寸改变、停用或卸载清理监听。起拖读取当前实际可见尺寸，移动直接更新当前面板的 `width / flex-basis` 和分隔条读屏数值，不逐像素写入 Pinia 或重渲染布局父组件，也不等待 rAF；手势结束才提交尺寸并保存，宽度在 Vue 完成提交后交还 CSS 管理。左栏变宽时同步限制右栏，保留聊天区域最小宽度。会话标题的中间省略测量按标题和字体缓存，避免拖宽时重复创建 Canvas 和测量全部候选。拖动期间暂去抽屉阴影，全页保持对应调整光标并禁止选字，分隔条用强调色显形 / 伸展反馈，参数由 `--resize-line-rest-scale`、`--resize-grip-rest-opacity`、`--resize-grip-active-scale` 和既有动效令牌控制；减少动态效果时取消过渡，宽高不加缓动延迟。双击还原与键盘调整不变。独立 Electron 实例经操作系统鼠标输入观察四处按住期间连续变化、松手保存及光标状态回收；左右宽度拖动期间布局父节点的尺寸样式未更新。此结果不代替用户实际会话的性能验收，未量化 Web 滚动或拖动帧率，未运行测试套件或构建。
- 宽度 ≤ 1100px 时抽屉为覆盖层；宽度 < 720px 时侧栏为覆盖层。断点来自 `_breakpoints.scss`，令牌导出给既有 JS 布局逻辑。桌面侧栏覆盖层从窗口栏下方开始，Web 侧栏从应用导航栏下方开始；抽屉覆盖层和遮罩始终从应用导航栏下方开始，避免挡住窗口按钮和导航。覆盖面板互斥，关闭复原焦点与滚动；宽屏非模态抽屉不设置焦点陷阱。
- **Settings**：分组导航 + 内容；窄屏变顶部导航。搜索定位 18 个真实字段，保留 `route.query.tab`；旧 `tab=workspace` 深链不变，显示名称按实际内容改为「运行状态」。

## 4. 签名组件

砚台中的“快速 / 均衡 / 深度”已替换为按模型能力展示的思考控制。强度使用有刻度的原生滑块，
含独立的服务默认位置；拖动预览，松手/键盘变更后保存。仅支持 on/off 时使用开关，不伪造强度档位。
运行中与保存中禁用，失败恢复已保存值，切模型清空旧选择；能力请求取消旧请求，避免慢响应串入新模型。
没有可控制能力时不显示滑块，只保留服务默认及原因提示。已知原生能力但兼容接口未接通也不冒充可操作。
本批未进行 GUI 运行验收。

### 4.1 轨道 Rail（Inkline 的核心）
- 正文左侧使用双 SVG 笔触，节点也用 SVG，不依赖字体字符；下列符号只是文档图例。
- 节点类型：
  - `○` 只读（读文件、搜索），连续的会合并成一个节点：「翻了 6 个文件」
  - `●` 有动作（执行命令、写文件）
  - `◇` 等你（审批 / 提问），用 `--wait` 色，节点会轻轻呼吸
  - `◆` 回合结束，后面跟回合小结
  - `×` 失败，用墨色并自动展开；朱砂保留给危险操作和驳回印记
  - `✦` 记下了一条记忆
- 节点右边是二级墨色摘要，点击就地展开详情：参数、输出、耗时、退出码。长输出有行号、复制反馈和折叠，最多渲染 200 行；失败自动展开。
- 模型实际提供的推理内容在回复前独立显示「思考」折叠区，不混入回复正文、工具参数或砚台。推理进行时默认展开，阶段结束后默认收起；用户手动展开/收起后，后续流式内容不重置选择。长内容独立滚动，Markdown 沿用现有安全渲染与节流；状态区播报开始/结束，不逐 token 播报正文。没有真实推理内容/事件时不生成假过程。
- 上下文仪表沿用后端 `measurement`，区分估算与服务端计数；聊天中只显示窗口数字、用量和可用百分比，不展示容量来源、获取时间或部署说明。来源及时间继续保留在运行时元数据，不新增 UI 来源标签。窗口未知时显示已有输入计数/估算和「窗口未知」，不绘制比例，不用产品预算代替窗口。摘要请求的输入不覆盖主对话仪表。
- 窗口按选中的模型配置关联：目录返回的容量逐模型保存；切换同名模型的服务配置或修改地址也不沿用旧窗口。运行前可显示容量，但输入量保持未知；当前会话的加载窗口和超限回执优先。没有容量数据时保持未知，不用固定数值或输出上限填充。
- 厂商 API / 中转站按服务声明和模型目录解析容量，不要求返回本地加载实例；自部署采用实际加载或服务配置，Ollama 复用官方 SDK 的 `ps` / `show`。公开 API 不探测 LM Studio 接口。标准 `/models`、`models` 列表 / 别名映射中的 `context_window`、`context_length`、`contextWindow`、`max_model_len`、`limit.context` 和 `max_input_tokens` 均按原始可调用模型 ID 读取；设置保存链路与 Core 解析链路保持一致。Anthropic 协议的中转站也可通过 SDK 模型列表补容量。
- 复用 models.dev 维护的公共资料，以生成的离线快照随 Python 包分发；已知模型无需等待联网即可取得容量。Core 在后台按 TTL 刷新目录，并在关闭时取消、等待刷新后再释放客户端；公网资料请求遵守环境代理，不改变模型调用的现有代理策略。目录更新失败不抹掉离线资料。仅精确身份、目录声明的别名 / 唯一原始模型关系参与匹配，不通过显示名相似度、量化后缀或任意前缀猜测容量。
- 离线快照用 `node scripts/update-model-catalog.mjs` 从公开目录机械生成，仅保留提供商、地址、模型 ID、容量、输入上限和原始身份，附来源、时间、摘要及 MIT 许可。它是容量资料，不替代服务端的可用模型列表；不发送凭证、用户选型、地址、提示词或用量。每个配置的目录容量继续通过现有工作区设置保留，配置身份变化后不复用旧资料。没有可靠条目时不照搬 DSH 的通用 262144 默认窗口。
- 前端仅持久化按模型配置关联的容量、来源与获取时间，绝不缓存会话用量到模型资料。切会话、刷新和临时获取失败时保留已知容量，不额外显示来源提示；当前会话中的实际加载 / 超限回执窗口优先于模型资料。缓存只在无新容量时回退，不能覆盖 Core 的新查询结果，也不参与后端预算计算。没有本会话输入回执时只显示窗口容量，不画 0% 圆环。后端已知窗口用于同一条压缩预算链路；目录额外声明较小输入上限时，同时遵守该上限。
- 空白对话、模型选择和窗口重新获焦时，通过 `models/{id}/context` 查询当前配置容量；查询可取消，旧响应不能覆盖新选择。查询只补容量，不复制其他会话的用量。旧三段容量键仅在配置 ID、协议、地址、模型相符且无新的显式容量时兼容；缺少配置身份的旧计数不猜测归属。
- 窗口详情展示可用输入预算、输出预留、安全余量与自动压缩阈值；输入计数与输出计数区分，避免总窗口占比低却预算已耗尽的误解。未知容量保留原因和重试入口，不绘制百分比。服务未提供资料时，设置页可逐模型填写已知容量；这是资料回退，不改变加载窗口。目录缺失容量不会清掉已保存的资料。
- 输入框下方直接展示「已用 / 窗口容量 Token」和可用的百分比，不把容量只藏在弹层中；没有本会话用量时显示「— / 容量」，未知容量保留计数并显示「窗口未知」，提供重试及模型容量设置入口。预算详情优先使用同窗口的本次执行回执，避免容量查询覆盖带思考设置的实际输出预留。
- 小窗口使用按容量缩放的请求预算：本次输出上限为配置上限与窗口四分之一策略上限中的较小者，显式思考预算的必要下限除外；已知容量预留 5% 安全余量（128–1024 tokens），输入预算再遵守目录提供的输入上限，提前压缩阈值为输入预算的 80%。这些比例属于产品请求策略，不是模型容量表；未知容量不据此编造窗口或提前压缩阈值。详情区区分本次输出预留与配置输出上限，不修改用户配置或模型服务的加载设置。
- 原生 LangChain 规划中间件使用精简的系统说明与工具说明，保留原生 schema、计划状态和审批约束；不再把默认长篇规划教程带入每次请求。请求参数通过公开 SDK 的浅复制调整，共享客户端仍由 Core 持有；摘要请求保留显式思考预算约束。缓存模型再次访问时按现有目录 TTL / 失败退避刷新容量资料，不因首次获取失败而永久未知，目录资料未变时不重复写入持久化设置。
- 已知容量按真实窗口决定提前压缩；未知时仅在明确服务端超限后尝试一次缩减与重试。固定指令/工具定义超预算显示「模型输入预算不足」。没有手动压缩按钮。
- 自动压缩按 `context.compaction.started / failed / skipped` 和 `context.compacted` 回执独立展示；聊天过程与砚台底部显示进行、完成、失败或跳过，失败原因直接可读，跳过不冒充完成。任务结束而缺少完成回执时标明结果未确认。窗口用量显示开关不隐藏压缩失败反馈；没有手动压缩接口，因此不显示对应按钮，也不增加未支持的模型思考控制。
- OpenAI-compatible 的扩展推理字段通过 LangChain 转换薄适配保留；Ollama 显示其真实返回的 thinking，不改变服务端 `think` 默认值；Anthropic / Responses 使用 SDK 标准内容块。别名只采用一份，可见摘要可展示，加密内容和签名不展示；流式内容与最终完整响应不重复追加。客户端仍由 Core 管理。
- 缓存命中数只来自服务端用量回执；兼容服务的扩展读取、写入和未命中字段在 SDK 转换入口保留，由 LangChain 聚合流式块，不另建计数器，也不把未命中当作缓存写入。统计覆盖本对话的主模型、摘要和子 Agent 请求；只有全部请求均报告输入与缓存读取、且数值一致时显示命中率。缺失时保留已报告的 Token 数，标明已报告请求数和数据不完整，命中率显示「—」，不补成 0%。
- 运行中的那段线用 `--accent` 色，从上往下“生长”。
- 长会话的滚动条位置显示**墨线缩略图**：节点密集的地方墨色更深，点击直接跳过去。
- 和主流卡片相比：正文读起来连贯，过程又一个不少。

### 4.2 脉点 Pulse
一个 10px 的图形，状态变化时形状跟着变，不只是换颜色：

| 状态 | 形态 | 颜色 |
| --- | --- | --- |
| 静息 | 实心圆 | `--ink-3` |
| 思考 | 圆形缓慢呼吸 | `--accent` |
| 行动 | 圆拉成短横线并左右移动 | `--accent` |
| 等你 | 菱形，轻微抖动一次后静止 | `--wait` |
| 出错 | 叉号 | `--ink-2` |

### 4.3 回合小结（Receipt）
纯聊天及没有以下四类记录的执行仅显示紧凑收尾。小结默认不铺明细，宋体标题与耗时一行、可点击的分类数量一行；只有点击分类后才出现虚线和明细：
```
◆ 执行小结                                      2m08s
  [改动文件 3 +42 −7 ▸] [执行命令 2 ▸] [等你处理 1 ▸]
```
- **改动文件**：列出真实变更和已成功写入 / 修改的文件，按当前执行所属工作区归一、去重。点击定位抽屉文件树并预览当前磁盘内容，不冒充执行时的历史版本；不在该工作区内或工作区已不存在的文件不能跨目录预览。
- **执行命令**：列出已记录命令，点击后复用操作详情显示输出、退出码、耗时与参数。输出只在展开时挂载，沿用长输出折叠和复制反馈。
- **等你处理**：列出该次执行的真实审批 / 提问，显示目标及准 / 驳印记；展开可查回答、理由和服务端已记录的批准范围。处理后的记录不依赖仅保存待审批项的会话 store，按需读取已有任务详情；缺失或截断明确提示，关闭分类取消未完成查询。这里只读历史，不新增审批授权或扩大范围。
- **失败**：列出失败操作的结果及执行级错误；旧记录缺少明细时明确说明，不通过数量反推或补造记录。
当前没有回合回滚接口，不展示「撤销本回合」或伪造文件接受 / 回滚按钮。

### 4.4 「等你处理」

- 当前会话的审批与提问就在 Rail 对应位置处理；不在视口内时，砚台上方提示「N 项等你处理 ↓」，点击定位并聚焦第一个操作控件。
- 非当前会话显示侧栏菱形标记；收起侧栏时开关显示计数，抽屉入口也显示计数。两处均不计当前会话。
- 抽屉的独立页签展示全部会话事项，标明当前对话，可直接处理或跳转定位；空态、加载与错误重试分别设计。
- 窗口失焦时沿用既有桌面提醒与动作，不在本轮改动 Electron。

### 4.5 审批卡片与「印记」
- 卡片：`--wait` 色左边框，标题说明要做什么，下面是等宽字体的具体命令或路径，再一行风险说明。
- 按钮：`允许 (Y)` · `驳回 (N)`，默认仅一次，保留审批 hash 与用户所见版本。服务端允许时可显式选择本任务/本会话的同范围授权，展示目录、固定命令参数或站点；不新增一键放行整个工具的 A。驳回时可以附理由且不创建授权。对话管理可查看有效期、撤销授权，撤销不停止已开始的操作。
- 提问使用真实 Question.title；为空时固定显示「Agent 在等你回答」，不切割、猜测或去重回复正文。
- 处理完后卡片收起，节点右侧留一个小印记：石青的「准」或朱砂的「驳」（12px 方形，宋体）。这是这套界面独有的小细节，只在这里用。

### 4.6 砚台 Inkwell（输入区）
- 底部浮动，圆角 14px，宽度和正文一致。
- 第一行是输入框（1–10 行自适应）；第二行是工具条：
  - 左：附件 · `@` 引用 · 模式胶囊 `问 / 谋 / 做`（对应 Ask / Plan / Auto，用中文单字）
  - 右：上下文墨量条（一根细横线，用得越多墨色越深）· 模型名 · 发送
- 「设置 → 外观与称呼 → 输入与状态」提供发送快捷键：默认 `Alt+S` 发送、`Enter` 换行，也可切换为 `Enter` 发送。`Shift+Enter` 始终换行；`Alt+S`、原有 `Ctrl/Cmd+Enter` 和发送按钮均沿用当前默认动作：空闲时发送，运行中加入队列。`↑` 编辑上一条，运行中 `Esc` 中断。已有保存的 Enter 偏好保留，未设置者采用新默认。
- 选择 `Enter` 发送后，可勾选「Enter 发送前二次确认」，默认不勾选。普通 Enter 使用现有确认弹窗，确认后才提交；取消保留草稿。弹窗属于当前草稿和会话，草稿、会话、模型、模式、运行状态或发送偏好改变时取消，组件退出时回收；输入法组合输入和长按重复按键不触发发送。该确认不影响 Alt+S、发送按钮或 Alt+Enter 队列。
- 输入区不常驻快捷键说明；首次聚焦时按当前发送方式提示一次，5 秒后消失，使用新版提示记录，在本地偏好中保存，新建对话和重启后不重复提示。禁用本地存储时仅保证本次启动内不重复；减少动态效果时仅做短淡入。
- `@` 弹出文件 / 会话 / 记忆的混合搜索；`/` 弹出命令。
- 运行中输入框不锁定，主按钮与正常发送快捷键默认加入队列，发送菜单使用「加入队列 / 立即发送」，停止是独立操作：
  - 主按钮、Alt+S、Ctrl/Cmd+Enter，以及配置后的 Enter 均默认加入下一回合队列，不自动引导当前任务；Alt+Enter 仍可排队。启用 Enter 二次确认时，运行中弹窗明确确认的是加入队列。Enter 选择换行时不提交。
  - 只有明确选择「立即发送」或点击队列项的同名操作，才提交现有 `/tasks/{id}/inputs`，在下一步之前纳入；已执行操作不撤回。状态显示等待纳入 / 已纳入 / 本轮未采用；未采用可作为新回合发送，不自动丢弃。
  - 队列在砚台上方可见，支持拖拽手柄调整先后，也支持聚焦手柄后使用上下方向键移动；显示插入线、拖动预览和落位过渡，减少动态效果时关闭过渡。直接重排按会话保存的同一个实际待发数组，不另存显示顺序；以消息 ID 定位，已出队的消息不可重排。编辑、移除、暂停后确认继续与失败保留原文不变；未增加跨重启持久化。
  - 等待审批时立即发送不可用，说明先处理审批；加入队列仍可用。普通输入不当作取消。
- 运行中可修改执行权限，从下一个尚未开始的工具生效；已开始操作持有权限快照，不被更改或中断。已有审批仍须明确决定并校验 hash / 版本，调整模式不是自动批准。
- 完全访问使用 `danger_full_access` 并就地二次确认，设置为新对话默认值还须风险勾选；旧自动模式单独标注，不自动提权。权限保存异常时查询实际状态，不自动重发或展示乐观降权。本次权限交互未做浏览器验收。

### 4.7 速记胶囊（桌面特有）
- 全局快捷键 `Alt+Space`（可改）唤出一个 560×56 的无边框置顶小窗，位于屏幕中上方。
- 输入后 `Enter` 发到最近的会话，`Ctrl+Enter` 开新会话；发送目标也提供可见选择。`Esc` 关闭。普通粘贴沿用系统行为，不声称已接入文件拖放。
- 主窗口不打开也能用，回复完成后用系统通知提醒。

### 4.8 「它记得」面板
- 从侧栏底部进入，单独路由 `/memory`。
- 上方身份区展示助手名称与人设，下方条目区展示偏好 / 记忆，不做三栏平均分配。人设继续用现有「人设：」前缀，数据格式不变。
- 分组空态就地添加；编辑就地展开，保存有「已记下」反馈；删除二次确认。置信度显示墨线和数字，搜索 / `route.query.focus` 定位保留。
- 每条都可以编辑、置顶、删除；Agent 新记住一条时，轨道上出现 `✦ 记下了：…` 节点，点击可撤销。
- 设置里可以给 Agent 起名，并选一个汉字当“头像字”（宋体），用在空态和托盘提示里。

### 4.9 抽屉
标签页：**等你处理**（跨会话）· **变更**（真实 diff，行号、滚动、复制）· **运行**（当前操作、等待原因、子 Agent、后台进程及停止，历史记录折叠）· **计划**（真实 `plan.updated`，无计划不编造）· **文件**（键盘文件树与预览）。聊天区负责输入、回复及补充状态。

- 文件树 / 文件预览与变更列表 / diff 预览均以水平分隔条调整占位，分别滚动；两页各自记住比例，窗口变小时保留两区可用空间。变更较少且未手动调整时列表紧凑排列。分隔条可用上下方向键调整，Shift 加大步长，Home / End 调到边界，双击或 Enter 复原；页签切换清理拖拽和尺寸观察，重新进入时重测可用高度。
- 文件与 diff 预览使用填满剩余高度的文档视图，所有已获取的行都可滚动查看，不套用聊天代码片段的前 20 行 / 最后 200 行折叠规则或 360px 高度上限。后端截断仍明确提示；代码标题和复制按钮不参与纵向压缩，操作区保留边距。
- 文件工具栏提供「新建空文件」「新建文件夹」「在文件资源管理器中打开文件夹」和刷新。选中文件夹时使用该目录，选中文件时使用其父目录，没有选择时使用工作区根目录；路径可查看完整提示。新建使用原生模态命名框，Enter 确认、Esc 取消，成功后刷新并定位，不覆盖同名内容，失败保留名称就地提示。创建仅接受已登记工作区内的单层名称，不递归补父目录、不写入文件内容、不修改 Git 元数据。桌面端复用现有受限 IPC；Web 端使用本机所有者接口打开文件夹，不能提交任意系统命令。
- diff 增删使用独立的浅 / 深色语义令牌，不随强调色预设改变：整行及行号区着色、侧边墨线区分，原文的 `+ / −` 与前后行号保留；列表和小票中的增删数量采用相同色彩。

## 5. 关键交互流程

1. **空态**：Chat 是写作起点，工作纸组织宋体问候、稳定随机的 MyGO 页边题记、应用图标落款、真实能力起手式与砚台。起手式只预填并聚焦，不自动执行。Overview 是个人工作记录，无对话时引导到 Chat，不做第二套首页。
2. **一轮任务**：发送 → 脉点进入思考 → 轨道开始长线 → 节点陆续出现并自动折叠 → 正文流式输出结论 → `◆` 回合小结。
3. **审批**：节点变 `◇`、脉点变菱形，就地确认后留下「准 / 驳」印记；其他会话的阻塞项才增加侧栏与抽屉入口计数。
4. **中断**：`Esc` 停止当前生成，轨道末端画一个「╳ 你叫停了」，已完成的步骤都保留。
5. **输入协作**：立即发送、加入队列、停止各自独立；未采用补充显式显示并提供重新发送。聊天分叉位于已保存助手回复下方的「⋯ → 从此处分叉新对话」，不再放在侧栏会话管理；携带该条回复的持久消息 ID，复制截至该回复的可见历史并打开独立会话。提示文件仍共享、不继承审批授权；源任务未结束时禁用并说明原因，无持久 ID 的流式回复不显示入口。支持键盘展开、Esc 收起与触屏点击，失败在原处显示且手动重试保留请求键。不展示逐节点执行分叉、worktree 或回滚。新增分叉未运行交互验收。
6. **滚动**：上滑后停止自动跟随，右下角出现「↓ 墨线还在长」按钮。

## 7. 状态设计
- **加载**：统一 InkLoader 与墨线骨架，不用通用 spinner；冷加载与刷新保留不同的内容密度。
- **断线**：WebSocket 断开时脉点变空心圆，标题栏下方出现一条 2px 的 `--wait` 细线；自动指数退避重连，重连后根据 `lastSeq` 补齐事件。
- **错误**：原因与重试靠近失败字段 / 分组；页面加载错误在顶部。轨道保留真实失败，没有单步重试接口时不伪造按钮。
- **超长输出**：节点详情最多渲染 200 行，代码有行号、折叠与复制反馈；不会为了展示重新执行工具。
- **焦点与读屏**：模态弹层复用原生 dialog 和现有焦点回收；覆盖抽屉保留焦点陷阱，宽屏非模态面板不困住焦点。树使用 roving tab stop；保存、Pulse 与补充状态按变化播报，图标动作提供可读名称。
- **设置反馈**：说明 / 字段 / 反馈三级排版；外观即时预览真实消息、节点和砚台。工具用途来自用户语言映射，模型说明折入详情；保存的 Secret 不读取回显，只能复制当前输入的新凭证。
- **产品边界**：数据管理当前只读统计；知识索引没有管理 API，不伪造加载 / 重建 / 删除。MCP 重试沿用现有整体应用接口，不声称单 Server 重连。

### 输入与恢复语义

- 运行中 Enter 默认引导：立即向现有 `/tasks/{task_id}/inputs` 提交，携带单次逻辑请求的 `Idempotency-Key`；只有实际 `running` 的普通任务可提交。等待审批/提问、排队、重试等待、停止中、直接 `/tool` 任务等不可引导，后端仍作最终校验。
- queued / consumed 直接使用 `task.input.queued`、`task.input.consumed` 事件；不添加补充输入轮询。没有 not_consumed 事件，因此任务结束、刷新与重连时通过现有 GET 查询确认；查询失败显示未知与重试，不从任务终态推断消费结果。
- 补充输入以 input ID 合并。消费后消息表中的同 ID 消息由补充条目承载，避免双份显示；同文不同 ID 的合法输入不去重。较新事件不被旧 GET 或迟到 queued 回执覆盖。
- 未采用的补充明确显示“本轮未采用”和“作为新回合发送”，必须用户点击，不自动重发。响应不明确时保留原幂等键；确认成功后关闭同一条补充的重发操作。已执行的动作不撤回。
- Alt+Enter / 发送菜单的“稍后发送”保留前端下一回合列表。列表可编辑、移除或立即引导；成功结束原任务后才自动发送，失败、取消、断线时暂停，需显式继续。此列表仍为当前前端实例的本地状态，不宣称跨浏览器刷新持久化。
- 草稿收到确认前保留；4xx 就地显示错误，20 条上限仅计算 queued。较新草稿不会被旧请求的成功响应清空。首次引导展示一次送达与副作用边界说明。
- Esc / 独立停止按钮走原取消接口，不把普通补充当取消。发送菜单打开时 Esc 只关闭菜单。
- 会话 snapshot 没有 inputs / plan。恢复用原事件历史、`GET /tasks/{id}/inputs` 和 `GET /tasks/{id}/inspection`，不增后端字段。初次刷新只补读最新任务和最近 20 个任务中尚未确认消费的输入；展开更早聊天时再按需确认，避免遍历全部历史发请求。

### 计划和抽屉边界

- `plan.updated` 只接受 `{content, status}` 的有效数组，按任务及真实序号整体替换；空数组明确清空。inspection 的 last_sequence 防止旧查询覆盖新计划，truncated 的缺失项不冒充空计划。
- 计划状态按步骤独立展示：未开始用中性色空心圆，进行中用墨点、强调色浅底与左侧墨线，已完成用强调色勾选；每项同时显示状态文字。进度只计该步骤真实的 `completed`，不从工具成功或任务结束推断整份计划已完成。Runtime 投影兼容同批工具的列表型 channel updates，保留中间计划更新；`write_todos` 仍由原生中间件整体替换，提示词要求保留未改动步骤，不在前端猜测或合并遗漏项。
- 显示名“任务”改为“运行”，保留既有 `jobs` 页签 ID 和 `JobsTab` 文件名。仅展示真实当前操作、等待原因、已派发子 Agent 和后端进程记录；历史运行默认折叠成一行摘要，用户完整输入留在聊天区。
- “计划”展示当前最新任务的真实步骤、进度、加载、错误重试或空态，不沿用上一任务计划，也不伪造步骤。“等你处理”保留阶段 2 行为。
- 只有运行页签打开且存在真实活跃进程时才刷新日志尾部；切换会话、关闭和卸载取消可取消的读取、清理计时器，迟到响应不覆盖新会话。API listTasks 沿用原签名，不能物理取消的请求只丢弃过期结果。
- 本阶段补充输入显示在所属任务过程之后，作为独立状态条目；3b 才加入 Rail 节点与 Minimap，不提前扩展时间线视觉。

### 逐项交付

| 要求 | 实现与边界 |
| --- | --- |
| SVG Rail | `RailGlyph` 用 SVG 圆、菱形、叉、记忆笔形和补充箭头绘制；`RailInk` 用填充曲线与细线建立粗细笔触。只有正在执行节点的线段叠加强调色，以 scaleY / opacity 生长，静态透明度渐变提供墨尾，不动画模糊或阴影。 |
| 节点状态 | 落笔使用既有 spring 令牌；等待为菱形，失败为朱砂 SVG 叉并自动展开。批准/驳回仍留下原有印记，不改审批版本提交。 |
| 补充输入 | `PresentationNode` 仅存在于展示层，未新增 Gateway DTO。每条补充独立挂在 Rail 上，沿用等待纳入、已纳入、未采用和手动重发。以真实创建时间对齐带时间的工具节点；消费事件 seq 不冒充提交时间。没有可比较时间时使用可用 seq，缺少可比较顺序时放在过程末尾，不猜测。输入会隔开连续读节点，避免跨补充指令合并；正文不再重复绘制该输入。 |
| 连续读取与审批 | 沿用已有只读聚合；带精确 toolCallId 的审批仍挂在对应操作后，不能被读取聚合吞掉。无顺序问题卡的末尾降级规则不变。 |
| Minimap | 从实际 DOM 位置 / scrollHeight 计算墨量桶，密集位置更深。折叠节点映射到其真实摘要位置；未渲染的分页历史不伪造坐标。点击仍使用原有展开、滚动与焦点定位。ResizeObserver / MutationObserver 经 RAF 合并；文本 delta 不触发全节点 DOM 扫描，卸载时解除观察与待执行帧。 |
| 消息 | 正文 15px / 1.7，过程与技术信息 12–13px；正文与页边过程保持分列。标题、列表、引用、链接、表格有独立层级，行数与小结数字使用 tabular-nums。 |
| 小结 | 结束按钮显式清除默认边框。纯聊天只留紧凑收尾；真实工具、审批、变更或其他活动保留小票，展示文件、命令、待处理次数、用时和失败项。小票轻落，reduced-motion 只淡入。未添加后端不存在的撤销接口。 |
| 代码 / 终端 / diff | 共用 `CodeBlock`：行号、无纸纹、20 行预览、展开最多最后 200 行、明确截断提示、完整原文复制及成功/失败反馈。diff 按实际 hunk 计算前后行号，保留增删行语义标记。工具参数仍折叠，不改变输出/错误提示来源。 |
| 砚台 | 聚焦墨晕只过渡 opacity；提交获确认后出现短促墨滴，失败不制造发送成功反馈。运行、等审批、待发列表有不同边缘形态；问/谋/做使用滑动墨块与不同形态，权限/规划前缀语义不变。提交中的反馈使用脉点，不增加通用 spinner。 |
| 键盘菜单 | / 和 @ 支持上下键、高亮滚动、Enter / Tab 确认、Alt+1–9 选择，Esc 先关菜单，IME 期间不提交。模型选择保留服务分组、搜索与原有 dialog 焦点恢复，增加 Home/End/PageUp/PageDown 和 Alt+数字；菜单选项不触发新的提交接口。 |
| 响应式与无障碍 | 沿用共享断点和两侧覆盖面板规则。1440 / 1100 / 719 × 浅/深色均截图，无整页横向溢出；保留停止、定位和重发按钮的可访问名称。动态节点、小票和活动线在 reduced-motion 下短淡入，墨滴关闭。 |

### 设计决策与限制

1. **第一眼是一张可以写的纸。** 问候、题记、目录式起手式和砚台属于同一个场景；强调色参与页边构图，不用居中 Logo 或四张欢迎卡。动效有终点，用户聚焦可立即终止可见性编排；弱动效设置只短淡入。
2. **记录页不再争夺首页。** 它回答“哪些需要处理、哪些在做、最近做过什么”，不制造宏大指标或第二个欢迎页。数据未知就保持未知，冷启动不增加全历史抓取。
3. **记忆是一份能改的档案。** 身份与条目有主次，编辑就在条目旁，成功才落下一句“已记下”；失败保留内容、删除仍确认，避免将置信度包装成准确性保证。

未完成 / 范围限制：

- 首次展示范围为主窗口渲染进程生命周期，页面刷新算新启动；没有修改 Electron 来跨窗口或主进程持久化动画标记。
- 不补齐模型侧记忆检索/注入，不暗示 Memory 页面条目已自动用于每一次模型调用；本阶段不新增后端配合接口。
- 工作记录仅使用已加载的执行事实；未读取会话状态明确显示未知，不保证冷启动便获知所有后台运行。
- 本轮未做真实模型/后端写入 E2E、Electron 原生窗口验收或独立 FPS/内存基准；视觉夹具、组件回归与构建不冒充这些结果。阶段 5 Settings 全面重塑与阶段 6 全站审校未提前展开。
