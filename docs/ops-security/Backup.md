# 数据备份与恢复

> 权威范围：个人数据备份范围、一致性与恢复流程。
> 当前没有完整自动备份/导出功能；以下是操作约束，不是已交付备份服务。

## 1. 范围

| 数据 | 处理 |
| --- | --- |
| 业务 SQLite | 核心：消息、任务、审批、偏好、记忆与审计 |
| 已启用的 LangGraph 检查点 | 执行恢复所需，独立于业务库 |
| 工作区文件 / 用户材料 | 核心：工具实际读写的产物，不等于数据库备份 |
| 天线项目（使用该扩展时） | 保存整个服务 `--root`：`.antenna-project.sqlite3`、求解目录、`.optimizations` 和 `.deliveries` 等原件；聊天副本或单个 ZIP 不能替代项目准入与全部来源记录 |
| 配置与本地 SKILL.md | 保存非敏感配置和无法重新获得的个人内容 |
| OS 凭证存储 | 独立处理；凭证存在状态不是敏感凭证备份 |
| 日志 | 按隐私/诊断需求保留，不默认全部上传 |
| 未来索引/包授权 | 能力交付后再纳入；索引应可重建 |

PostgreSQL/对象存储/SkillGrant 不属于当前备份对象，不能因旧方案有这些名字就声称覆盖。

## 2. 一致性

SQLite 使用 backup API 或已停止写入后的完整一致性快照，不直接复制活动 db 文件而遗漏 WAL。业务库与检查点各自一致，不等于文件和全部存储全局原子一致。

天线项目库同样遵守 SQLite 一致性要求。备份前等待服务计算和导出结束，再保存整个结果根目录；不要只复制 `.deliveries` 或只恢复数据库。恢复后先查 project_status 并核对原件，不要把缺少原项目库的新目录当作原项目继续。限额依赖可信本机操作员保留记录，不保证抵抗手工删库或篡改。项目不保存可续跑的优化种群，恢复文件不等于恢复执行。

需要恢复审批与副作用时，应先停止新任务、取消/等待活动运行实例、关闭资源，再记录数据库、检查点和文件的关联版本/时间与摘要值。不能仅恢复 UI 投影就认定运行时可续跑。

若做备份自动化，优先复用 SQLite/系统已有能力；记录应用/结构定义版本、对象范围与校验信息，不新建通用备份平台。

## 3. 保护与保留

备份可能包含聊天、文件和审批敏感信息，限制读权限并由用户选择存放位置。若需归档加密，先一致性快照/校验，再压缩和认证加密；使用成熟工具，密钥与备份分开。此流程尚非应用内自动功能。

按用户需求确定频率、副本位置、保留期和恢复目标，不固化企业 RPO/RTO、云上传或不可变存储。删除/遗忘说明必须包含备份保留影响；旧凭证不能因恢复回滚而重新授权。

## 4. 恢复

```text
选定备份并校验范围/版本/hash
→ 恢复到隔离副本
→ 检查 schema 与应用兼容
→ 校验 Workspace/消息/审批/文件
→ 检查所用 checkpoint 和恢复资格
→ 用验证后的副本切换
```

不直接覆盖仍在写入的目录。版本不兼容或关联不一致时停止切换，保留原数据；恢复失败不能靠反复启动触发副作用。

运行恢复边界见 [智能体运行时设计](../design/AgentRuntime.md)：浏览器 session 易失，旧任务无 checkpoint 时不能恢复执行，file_write 有有限内容状态核对但无通用恰好一次（exactly-once）。

## 5. 演练

在副本验证数据库完整性、消息顺序、审批摘要值/版本、任务终态、文件结果与检查点。校验成功不代替一次完整恢复演练，实际恢复耗时、缺失范围和失败项需记录。

桌面升级/回滚见 [构建与发布指南](../deployment/ReleaseGuide.md)。未来索引接入后再验证源删除传播和重建，不把尚不存在的索引测试当当前通过。
