### 2026-11-25 复审修正：保存期离页、首条消息一次创建、悬浮提示与聚合兜底

- 模型草稿：保存进行中离开设置页不再放行。此前守卫在保存期间把草稿排除在保护之外，保存失败时 API Key 与模型选择随编辑器卸载丢失；现在保存期间阻止离开和返回模型列表，与安全页的做法一致，请求层 30 秒超时保证不会被长期拦住。草稿判定没有另加一层：已有服务沿用 `isDirty`，新建服务与打开时的指纹比较。
- 首条消息：空白页首发改为带权限模式、记忆开关、模型和思考等级一次创建会话，去掉创建后的三次分步更新，不再留下只写入一部分设置的空会话。后端 `ConversationCreate` 原本就在一次请求内校验并写入这些字段，后端未改。创建失败时留在空白页、草稿不动；创建之后发送失败沿用 store 原有的报错（含「确认提交结果」提示），不再被覆盖成不带提示的文案。开发 Mock 的创建接口同步应用这些字段。
- 悬浮提示：350ms 等待期间按键、按下、窗口失焦或页面隐藏现在会取消尚未显示的提示，此前关闭监听只在显示后才注册。等待结束但不满足显示条件时释放监听。
- 聚合脉点：当前对话已归档且出错时，兜底不再绕过归档过滤把出错带回标题栏和托盘。「运行」面板向抽屉标题行暴露已有的读取状态，读取进行中刷新钮不可用，不再安排下一轮读取。

### 2026-11-25 天线优化改为内存评分与延迟发布

- `optimize / design` 的候选不再为评分发布目录：每个频点仍先经 SQLite 准入，再在 worker 内存中求解，并按与磁盘证据相同的规则（`evaluation._measure_point`）计算逐点指标、评分与达标判定；未入选候选只写 candidate-NNNN.json 摘要（参数、已准入 run_id、逐频增益/F/B/R+jX/SWR、评分或失败原因），远场与复电流文件读写为零。内存只保留当前候选与待发布最佳的全频结果，不随候选总数累积。
- 完整证据只属于最佳候选，在首次可评价、完整一代结束且有改善、搜索干净收尾或找到达标候选时发布：先写入与 solve 相同的数值目录，核对输入身份、完成标记与 hash，写下 published-NNNN.json 发布记录后才原子替换 progress.json；发布自带的回执保存即最终内容，不再二次替换。切换前中断返回上一份完整最佳（此前没有则 best=null），切换后丢回执直接取回新最佳；搜索因异常失败不重试发布，半成品目录保留、上一份已提交最佳不变。project_status 新增 `summary_only` 与 `get_optimization` 下一步，区分按策略只留摘要、未完成与已发布证据缺损（回执或发布记录已引用但目录缺失标 `corrupt`，曾被发布后替换的最佳同样适用）。收尾预留按首次发布实测耗时的 1.5 倍扩展；收尾发布失败记 `failed`，不拿过期最佳冒充干净结束。不退额度、不自动重放、不为归档重新求解。
- 普通 solve、旧目录、旧回执与已发布 ZIP 不变。数值目录的 `environment.json.elapsed_seconds` 现只计求解时间，不再包含数值文件写入。
